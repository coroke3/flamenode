## Notes (what changed in behaviour-neutral ways, and what was measured)
- L1: `apps/api` is typecheck-only. `tsconfig.json` is `noEmit` + `allowImportingTsExtensions`, with no `paths` override, so it inherits the root `paths` (src of domain / db / server-core / contracts). `build` is `tsc --noEmit`. `rg "apps/api/dist|@flamenode/api/dist"` finds no consumer outside this work item and the Work Order. CI still runs `npm run build --workspace=@flamenode/api`.
- L2: `dbMiddleware` (`apps/api/src/middleware/db.ts`) builds `drizzle(c.env.DB, { schema })` once per write request, after `writeGuard` (admin routes: `onlyMutating`; videos: last item of `videoWriteStack`). The events routes inherit the admin `*` middleware. Routes read it with `c.get("db")`; guard / preflight reads stay raw D1 (no behaviour change, no extra read). `scripts/check-server-core-boundaries.mjs` now fails on `drizzle-orm` / `@flamenode/db` imports in `apps/api/src/routes/**` (test T06).
- L3: `preloaded` is optional on the core `AtomicAuditMutationInput` and `prepareAuditLogEntries`; Next passes nothing (src/lib bridges unchanged; auditRestoreGolden and src/lib/audit tests PASS).
- Routes now write statements with the sql template tag wrapped in db.run (same SQL text and params; the golden compares whitespace-normalised text). The announcement queue row uses core `buildAnnouncementChangeQueueBatch` (drops `requestedByUserId`, as CURRENT and as the copy did); chapters use core `buildStaticRebuildQueueBatch` for target `video` (priority "normal").
- The two `expectedRowCondition` copies (apiEndpoints.ts, templates.ts) are replaced by the core one; the unit test compiles it with `SQLiteSyncDialect` and keeps the same three assertions.
- Fake D1 (`apps/api/test/helpers/sqliteD1.mjs`) gained `.raw()` and the missing `system_settings` columns (drizzle `select()` lists every column); `chapterSeed.atomicD1` already had `.raw()`.
- Tests that imported the copy were re-pointed without dropping any case: `adminGuards` (preload vs self-read now through the core + drizzle fake, reads 2 vs 0 and equal rows), `auditParity` (14 tests: the 10 entry cases now run the core with `preloaded` and a db that throws on any use, against CURRENT's reading path; the queue and audit INSERT tests compare the batch the real route sends against CURRENT), `videoChapters.parity` (core builder vs CURRENT), `eventTemplates` (core `expectedRowCondition`).
- `generateId`: the copy threw `secure_random_unavailable` without `crypto.randomUUID`; the core falls back to `getRandomValues` and throws only without both. Workers always have `randomUUID`.
- Bundle (esbuild, minify, same flags before and after, no wrangler config exists for apps/api yet so `wrangler deploy --dry-run` is not possible; MIG-0628 owns it): origin/main 436,004 bytes / 116,122 gzip; this branch 593,458 / 153,304 gzip (+157 KB, +37 KB gzip: drizzle sqlite-core + d1 driver, the full schema, the core audit / static rebuild modules). Well under the Workers Free 3 MB compressed limit. Request CPU is NOT measured (L2 target: +2 ms or less per route; MIG-0606 measures before / after on the same route; STOP if above).
- 1102: no Worker was run; Runtime class S3 budget unchanged on paper (3 pre-reads + 1 batch per route, asserted by the existing D1-budget tests and the golden `reads` field: unchanged).
