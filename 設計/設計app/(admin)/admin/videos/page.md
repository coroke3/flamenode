# 投稿動画管理・審査ページ設計 (`/admin/videos`)

## 2. デザイン方針

- **コンセプト**: "The Vigilant Lens" (コンテンツの品質を守る)
- **レイアウト**:
    - **左側**: システム全体の管理ナビゲーション。
    - **右側**: 
        - **レビュー・ワークスペース**: 未審査動画を「高速審査モード（後述）」で表示するメインエリア。
        - **統計バナー**: 現在の審査進捗（済/未）と、YouTube API Quota の残量をリアルタイム表示。
- **視覚演出**: 未審査動画のカードには `--accent-primary` のボーダーを付与し、視認性を高めます。承認済み動画は `--bg-surface` 背景で落ち着いた表示にします。
- **高速審査モード**: 埋め込みプレイヤーを中央に配置し、キーボードの `A` (Approve), `R` (Reject), `S` (Skip/Next) で即座にステータスを更新し、次の動画へ自動遷移するワークフロー。
- **審査ポリシー**: 基本的に全動画は審査を通過する。旧データの一括インポートは審査対象外とし、審査中はフロント表示を「ユーザー名のみ」に制限する。

## 3. 目次・機能一覧
1. **全動画一覧・検索・フィルタリング機能**: 申請状況等による動画の絞り込み
2. **動画審査・承認トグル機能**: `status` の切り替え
3. **動画情報の強制編集機能**: 運営によるメタデータの修正
4. **動画ソフトデリート対応・復元機能**: 論理削除の実施と履歴表示
5. **審査例外 (Legacy Import) 対応**: 旧データの一括インポートは審査不要
6. **仮登録の限定公開ゲート**: 審査中はユーザー名のみ表示

## 4. 各機能の詳細解説

### 1. 全動画一覧・検索・フィルタリング機能
*   **役割:** システムに存在する膨大な動画データを、運営が目的別に素早くピックアップする。
*   **内部ロジック:** テーブルUI（DataGrid等）を用いて `videos` の一覧を表示。以下のフィルタリングを実装する。
    *   承認ステータス（承認済 `public` / 審査中 `pending` / X ID再申請中 `x_reapply_required` / 差し戻し `unlisted` / 無効化 `voided` / 全て）
    *   公開設定（`"public"` / `"unlisted"` / `"private"`）
    *   削除状態（有効 / 論理削除済）
    *   審査対象（通常 / インポート済）
    *   仮登録（審査中のみ表示）
    *   イベントID、投稿者名、タイトルでの部分一致検索

### 2. 動画審査・承認トグル機能
*   **役割:** 新規投稿された動画がレギュレーションを満たしているか確認し、一般公開の許可を出す。
*   **内部ロジック**: テーブルの各行、または詳細モーダルにて `status` を更新する。`"public"` になることで、一般ユーザーの `/list` や各一覧画面に作品が露出するようになる。`x_reapply_required` は通常の `pending` と同じ審査列に出し、専用タブには分けない。審査中は「ユーザー名のみ」表示で、承認後に全情報を公開する。操作時は `history_logs` に変更履歴を保存する。

### 3. 動画情報の強制編集機能
*   **役割:** 不適切なクレジットや誤った使用編集ソフト情報など、ユーザーの手を離れて運営が修正すべき項目を直接編集する。
*   **内部ロジック:** 各動画の「編集」ボタンから管理者用フォームを開き、D1の `videos` テーブルに対して `UPDATE` 文を発行する。権限を持つ管理者のみ実行可能。

### 4. 動画ソフトデリート対応・復元機能
*   **役割:** 誤作動やスパム対応時に、データを完全に消し去らずにフロントエンドから隠す。
*   **内部ロジック:** 動画の「削除」ボタン押下時、ドキュメント自体は削除せず `is_deleted = true` をセットする。削除済みフィルタをかけた際のみ表示され、「復元」アクションで再度 `false` に戻すことが可能。

### 5. 審査例外 (Legacy Import) 対応
*   **役割:** 旧システムや過去データの一括移行を、審査フローに滞留させない。
*   **内部ロジック:** インポート処理では `status = "public"` を初期値に設定し、審査一覧のデフォルト対象外とする。必要に応じて「インポート済み」トグルで一覧に再表示できるようにする。

### 6. 作品編集許可項目の設定機能
*   **役割:** ユーザーが自身の作品をどの範囲まで修正できるかを一括制御する。
*   **内部ロジック**: 
    *   **全体設定 (Global)**: `system_settings` の `default_editable_fields` を更新する UI。チェックボックス一覧（タイトル、音楽、クレジット等）を表示。
    - **イベント別オーバーライド**: 各イベントの設定画面、または動画一覧のイベントフィルタ経由で、当該イベント限定の `editable_fields` を設定可能にする。
    - **動的適用**: ダッシュボードの編集画面表示時に、この優先順位に基づいた JSON を取得し、フロントエンドの `disabled` 属性を制御する。

### 7. 仮登録の限定公開ゲート
*   **役割:** 審査中の段階では個別作品の情報開示を抑え、公開後に全面表示する。
*   **内部ロジック:** `status = "pending"` の間はフロント表示を「ユーザー名のみ」に制限し、タイトル・説明・YouTubeサムネイル・クレジット等は非表示とする。承認後に全面解放する。

## 5. 詳細UIロジックとステート管理

### 4-1. 高速審査ワークフロー
*   **クイック審査モード**: 動画を埋め込みプレイヤーで連続再生しながら、キーボードのショートカット（例: `A` で承認、`D` で削除保留）で次々とステータスを更新できる専用UIを実装します。
*   **バッチ処理**: チェックボックスで選択した複数の動画に対し、「一括承認」「一括削除」を `UPDATE videos SET status = 'public' WHERE id IN (...)` のバルククエリで実行します。

### 4-2. データ整合性の維持
*   動画を「承認」した際、関連する `slots` テーブルのステータスを自動的に `"submitted"` に同期させるトランザクションを実装し、データの不整合を防ぎます。
*   `x_reapply_required` の作品は、X ID 再申請承認と枠取り直しが完了したら自動的に `pending` へ戻す。旧却下 X ID は公開せず、管理画面の履歴だけで確認できる。
*   `voided` 操作は作品IDまたは `VOID` の確認入力を求める二段階確認必須とする。本人向け通常表示は「不備」、詳細文は通知内だけで扱う。管理者統計にはイベント別・理由カテゴリ別で通常作品と別枠表示する。
*   `voided` 作品は既定の管理画面検索では非表示にし、ステータスフィルタで明示した場合のみ表示する。復旧は管理者専用、イベント編集許可者は担当イベント内で復旧要請のみ可能。
*   `voided` 作品の YouTube ID は重複判定から外し、コメント、チャプター、いいね、ブックマークは非表示保持する。再登録時に旧データは引き継がない。

### 4-3. リアルタイム・アップデート
*   他管理者が同時に審査を行っている場合、重複作業を防ぐために SWR 等のポーリングで最新の承認ステータスを監視し、リアルタイムに一覧に反映させます。

### 4-4. 審査中の情報マスキング
*   **表示制御**: 審査中は一覧カード・詳細ページともに「ユーザー名 + 審査中バッジ」のみを表示する。
*   **解放タイミング**: `status = "public"` への更新と同時に全フィールドを公開。

### 4-5. インポート動画のスキップルール
*   **判定**: 旧データの一括インポートは審査対象外として登録し、管理者の手動操作でのみ再審査対象へ戻せる。
*   **ログ**: インポート経由の登録は `history_logs` に「import」由来を明記する。

## 6. YouTube API 更新ポリシー (Lazy Update)

- **役割**: Google のクォータ制限を考慮しつつ、データの鮮度を維持する。
- **内部ロジック**: 
  - 投稿・編集フォームで YouTube URL / ID が入力された時点、保存時、提出時に即時同期を試行する。
  - ユーザー本人の手動同期要求は1作品につき1日1回まで許可し、日本時間 0:00 に上限をリセットする。管理画面では管理者と担当イベントのイベント編集許可者が必要に応じて再同期を実行でき、この操作は通常ユーザーの1日1回制限の対象外にする。
  - YouTube API クォータ不足で同期要求をキューに入れた場合、翌日の日本時間 0:00 以降に自動再実行する。
  - Shorts URL、通常URL、共有URLはいずれも11桁の動画 ID に正規化して扱う。
  - 非公開動画は本人へ公開設定確認を促す。削除済みや存在確認失敗は `youtube_sync_status = "failed"` のままユーザー修正待ちにし、`pending` へ戻さない。
  - プレミア公開待ち、年齢制限付き、埋め込み不可動画は登録自体をブロックしない。埋め込み不可の場合は警告と外部再生導線を出す。
  - YouTube API の1日上限クォータを90%消費した時点で OGP 解析へフォールバックする。
  - OGPやAPIから取れたタイトル・サムネイル・公開予定時刻は確認・提案用に留め、ユーザーの入力を勝手に上書きしない。
  - 埋め込み不可または年齢制限で iframe 再生できない場合は、サムネイルと「YouTubeで視聴する」外部リンクをプレイヤー中央とタイトル直下に表示する。
  - YouTube側再生数は6時間ごとのバッチで同期し、取得失敗時は前回値を維持する。
  - 作品の `youtube_sync_status` が最終更新から 6時間以上経過している場合、詳細表示やリスト描画時に非同期で YouTube Data API へリクエストを送信。
  - **403 (quotaExceeded)**: API制限時はその日のリトライを中止し翌日へ持ち越し。
  - **404 / Private**: 削除済みまたは存在確認失敗は `youtube_sync_status = "failed"` にし、非公開は本人へ公開設定確認を促す。作品 `status` は自動で `pending` に戻さず、YouTube 側の復旧または URL 修正を待つ。
