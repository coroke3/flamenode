# FlameNode Implementation Plan

## Executive Summary

FlameNode is a Japanese video platform built on Cloudflare's serverless stack. Based on comprehensive codebase exploration, **most core features are already implemented**. The primary work remaining is **compliance verification, test coverage gaps, and minor refinements** rather than building from scratch.

## Current State Assessment

### Fully Implemented
- **ID/Authorization System**: Discord ID / X ID / Active X ID separation with 10-step WriteGuard
- **RBAC**: `ownership.ts` (593 lines) with 4 privilege modes and section-based video editing
- **Video CRUD**: Complete with section-based permissions, YouTube ID validation
- **Slot Management**: Reservation groups, consecutive slots, partial release, extension
- **Chapter Comments**: Time-linked comments (not independent comment threads)
- **Public API**: Whitelist protection with `FORBIDDEN_PUBLIC_KEYS`
- **Health/Security Checks**: Comprehensive audit and integrity checks
- **Admin/Manage Separation**: `/admin` (admin-only) and `/manage` (event staff)
- **Notification System**: Discord integration with outbox queue
- **27 Database Migrations**: Schema evolution complete
- **5 Cloudflare Workers**: Cleanup, notification-dispatcher, json-generator, score-recalc, youtube-sync

### Known Gaps
1. **Path References**: AGENTS.md references `.Codex/flamenode/` but actual files are at `.claude/flamenode/`
2. **Missing File**: `Codex-subagent-assignment.md` doesn't exist; equivalent is `claude-code-subagent-assignment.md`
3. **Test Coverage**: Unit tests exist for utilities but coverage gaps for core auth guards and server actions
4. **TypeCheck/Build**: Need to verify current state passes all checks

## 新タスク: メンバー構成セクションの整理

### 問題
`app/(manage)/manage/events/[id]/staff/page.tsx` の `StaffOverview` コンポーネントで、同じメンバーが「代表・運営」と「共同編集権限」の両方に表示される。

### 原因
- `representatives` + `editors` → 「代表・運営」に含める
- `collaborators`（permission_keys がある）→ 「共同編集権限」に含める
- しかし editor は同時に permission_keys を持つことがあるため重複する

### 修正方針

#### 1. 重複を解消: メンバーを1つのグループにのみ配置
優先順位: 代表・運営 > 共同編集権限 > その他

```typescript
// 修正後のロジック
const representatives = rows.filter((row) => row.role === "representative");
const editors = rows.filter((row) => row.role === "editor");
const editorIds = new Set([...representatives, ...editors].map((r) => r.id));

// 代表・運営に含まれないメンバーのみを共同編集権限に含める
const collaborators = rows.filter(
  (row) =>
    !editorIds.has(row.id) &&
    (permissionKeysByStaffId.get(row.id)?.length ?? 0) > 0,
);

// どちらにも含まれないメンバー
const others = rows.filter(
  (row) =>
    !editorIds.has(row.id) &&
    (permissionKeysByStaffId.get(row.id)?.length ?? 0) === 0,
);
```

#### 2. 権限タグを簡潔に
- 代表・運営カードでは権限タグを非表示（全権なので不要）
- 共同編集権限カードでのみ権限タグを表示
- 承認日時の表示を `YYYY/MM/DD` のみ（ユーザーIDは非表示）

#### 3. レイアウト改善
- カードの gap を 10 → 12 に調整
- バッジ行の色を整理（代表=accent, 運営=soft, 公開=soft, 非公開=neutral）
- 権限タグは最大5件まで表示、超過時は「+N件」で省略

### 変更ファイル
- `app/(manage)/manage/events/[id]/staff/page.tsx` (StaffOverview, StaffCard)

### 検証
1. `npm run typecheck` が通ること
2. 同じメンバーが2つのセクションに表示されないこと
3. 代表・運代表・運営メンバーには権限タグが表示されないこと
4. 共同編集権限メンバーには権限タグが表示されること

```typescript
function StaffGroup({
  title,
  rows,
  permissionKeysByStaffId,
  showPermissions = false,
}: {
  title: string;
  rows: StaffRow[];
  permissionKeysByStaffId?: Map<string, string[]>;
  showPermissions?: boolean;
}): React.ReactElement {
  return (
    <section className="fn-card" style={{ padding: 16 }}>
      <div className="fn-console-badge-row" style={{ justifyContent: "space-between" }}>
        <h3 className="fn-console-card-title" style={{ margin: 0 }}>{title}</h3>
        <span className="fn-badge fn-badge-soft">{rows.length}件</span>
      </div>
      {rows.length === 0 ? (
        <p className="fn-console-note">該当するメンバーはいません。</p>
      ) : (
        <div
          style={{
            display: "grid",
            gridTemplateColumns: "repeat(auto-fit, minmax(min(100%, 260px), 1fr))",
            gap: 10,
            marginTop: 12,
          }}
        >
          {rows.map((row) => (
            <StaffCard
              key={row.id}
              row={row}
              permissionKeys={showPermissions ? (permissionKeysByStaffId?.get(row.id) ?? []) : []}
            />
          ))}
        </div>
      )}
    </section>
  );
}
```

### `src/lib/auth/costGuardFeatures.test.mjs`

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";

/**
 * costGuardFeatures.ts のテスト。
 *
 * costGuardFeatures.ts は `import "server-only"` を含むため、直接 import できない。
 * parseFeatureList のロジックを再実装してテストする。
 */

function parseFeatureList(raw, column) {
  if (!raw) return [];
  try {
    const v = JSON.parse(raw);
    if (Array.isArray(v) && v.every((x) => typeof x === "string")) {
      return v;
    }
    console.warn(
      `[costGuard] ${column} is not string[]; treating as empty (fail-open)`,
    );
    return [];
  } catch (e) {
    console.warn(
      `[costGuard] failed to parse ${column}; treating as empty (fail-open)`,
      e,
    );
    return [];
  }
}

// --- テスト ---

test("parseFeatureList: null → 空配列", () => {
  assert.deepEqual(parseFeatureList(null, "test"), []);
});

test("parseFeatureList: undefined → 空配列", () => {
  assert.deepEqual(parseFeatureList(undefined, "test"), []);
});

test("parseFeatureList: 空文字 → 空配列", () => {
  assert.deepEqual(parseFeatureList("", "test"), []);
});

test("parseFeatureList: 有効な JSON 配列 → 配列", () => {
  assert.deepEqual(
    parseFeatureList('["post_video_unslotted", "edit_video"]', "test"),
    ["post_video_unslotted", "edit_video"],
  );
});

test("parseFeatureList: 不正な JSON → 空配列 (fail-open)", () => {
  assert.deepEqual(parseFeatureList("{invalid", "test"), []);
});

test("parseFeatureList: 配列でない JSON → 空配列 (fail-open)", () => {
  assert.deepEqual(parseFeatureList('{"key": "value"}', "test"), []);
});

test("parseFeatureList: 数値を含む配列 → 空配列 (fail-open)", () => {
  assert.deepEqual(parseFeatureList('[1, 2, 3]', "test"), []);
});

test("parseFeatureList: 空配列 → 空配列", () => {
  assert.deepEqual(parseFeatureList("[]", "test"), []);
});

// --- セキュリティ: CostGuard のフェイルオープン確認 ---

test("セキュリティ: parseFeatureList は fail-open (全停止を避ける)", () => {
  // 不正な JSON でも空配列を返し、全停止しない
  const result = parseFeatureList("not-json", "test");
  assert.deepEqual(result, [], "不正 JSON でも空配列を返す");
});

test("セキュリティ: parseFeatureList は型チェックを行う", () => {
  // 数値配列は受け付けない
  const result = parseFeatureList("[123]", "test");
  assert.deepEqual(result, [], "数値配列は空配列を返す");
```
