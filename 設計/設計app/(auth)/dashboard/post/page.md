# 作品投稿・編集フォーム設計 (`/dashboard/post`)

## 1. 概要
枠確保済みユーザーが作品情報を入力・提出するためのフォームページです。枠あり投稿 (`/dashboard/post/slotted`) と枠なし投稿 (`/dashboard/post/unslotted`) の共通フォーム基盤を提供します。

## 2. デザイン方針

- **コンセプト**: "Creative Gateway" (創造を世に送り出す扉)
- **レイアウト**:
  - **全体**: 左右分割を最小限にした**縦長マルチステップ形式**。
  - **ステップ管理**: 
    - 「1. 基本情報の入力 (Entry)」→「2. 合作メンバーの登録 (Optional)」→「3. 確認 (My Pageへ)」
    - ユーザーが最も負担を感じる「詳細情報（YouTube IDや制作エピソード）」を、この初期フローから切り離し、マイページから後日入力可能とすることで、まずは「枠の確保」に集中できる体験を提供します。
  - **確保済み情報の固定表示**: フォーム最上部に、確保済みの「参加イベント名」と「スロット情報」を Glass Tile で明示。

- **視覚演出**: `FlameNode-Design-System.md` のトークンに合わせ、背景は `--bg-base`、入力フィールドは `--bg-surface`、フォーカス時は黄色の `--accent-primary` のグローを適用します。
- **体験**: 確保した枠がない状態でこのページにアクセスした場合は、「まずは枠を確保してください」というガイド付きの空状態（Empty State）を表示し、ダッシュボードへ誘導します。

## 3. 機能一覧とデータ処理

### 3-1. エントリー時必須項目 (Step 1)
- **参加部門 (submission_type)**: ラジオボタン（個人 `individual` / 複数人 `collab` / 混合 `collab`）。選択時にメンバー登録ステップの表示/非表示が動的に切り替わります。
- **活動名 / チーム名 (display_name)**: テキスト入力。
- **読み方 (display_name_yomi)**: フリガナ等。
- **代表者 X(Twitter) ID (contact_x_id)**: アクティブ ID を初期値としてセット。
- **映像歴 (declared_experience)**: 数値または選択式。
- **アイコン画像 (icon_url)**: 
  - **クライアント側処理**: 必ず **250x250px** にリサイズ・圧縮してアップロード。
  - **履歴再利用**: `x_user_icons` から過去のアイコンを一覧選択できるUI。
- **作品基本情報**: タイトル、使用楽曲名、楽曲作者名、楽曲URL、ひとこと (30文字)。

### 3-2. 合作メンバーの登録 (Step 2)
- **表示条件**: 参加部門が「複数人」「混合」の場合のみ表示。
- **検索ロジック**: `x_users`、`x_user_aliases`、過去の `video_members`、旧データ由来の名前・ID対応表から候補を作り、**レーベンシュタイン距離**を用いたあいまい検索を実装。
- **手動追加**: サジェストにないメンバーもテキスト入力で追加可能 (`x_user_id: null`)。
- **詳細入力**: 各メンバーに対する「役職 (role)」「コメント (comment)」をアコーディオン形式で入力。

### 3-2-1. 名前・ID 相互提案
- メンバー入力では、名前から X ID、X ID から名前の両方向サジェストを行う。
- 入力欄はカンマ区切りの複数入力に対応し、縦に貼り付けた表データは改行をカンマ区切りへ変換できる。
- 候補には「完全一致」「部分一致」「類似一致」「旧ID alias」「過去メンバー履歴」の根拠を小さく表示する。
- 完全一致が1件のみの場合は自動選択し、複数候補や信頼度が低い候補はユーザーが手動選択する。
- 未登録の名前は `x_user_id: null` のメンバーとして保存でき、必要に応じて後から X ID 連携できる。
- 類似度はレーベンシュタイン距離で算出し、30%以下は候補から除外、50%未満は低信頼候補、80%以上は高信頼候補として扱う。
- 旧データの `creator/tlink` と `member/memberid` のカンマ区切り対応を候補データとして展開し、同じ `name + id` は1件へ重複排除する。

### 3-2-2. イベント協力者権限との関係
- 協力者は作品単位ではなく、イベント単位で管理する。
- 投稿者は通常、投稿フォーム上で協力者を追加しない。協力者の追加・権限設定は、管理者またはイベント編集許可者がイベント管理画面で行う。
- 協力者は、作品クレジットに載る合作メンバーとは別に管理する。クレジット掲載だけでは編集権限を付与しない。
- 協力者が後から作品編集画面へ入った場合、対象作品が属するイベントと `event_collaborator_permissions.permission_key` を確認し、許可された項目だけを活性化する。
- 権限キー例は `videos.music_credit`, `videos.members`, `videos.review_data`, `videos.youtube_id` など。本人承認は不要。

### 3-2-3. CSV 入力とプロンプトコピー
- メンバー、使用編集ソフト、カスタム質問回答など、複数値を扱う入力欄には「通常入力」「CSV入力」タブを用意する。イベント協力者権限の CSV はイベント管理画面で扱う。
- CSV 入力欄の横に「CSV作成プロンプトをコピー」ボタンを置き、対象欄に必要な列名、例、出力形式を含むプロンプトをコピーできるようにする。
- CSV 取り込み後は、名前・ID サジェストを通して未確定行を表示し、保存前に候補選択または手動入力へ進める。
- 既存メンバーへ反映する場合は「追記」を既定かつ基本動作にし、自動更新は行わない。重複候補はプレビューで警告する。

### 3-3. YouTube ID・詳細項目（後日入力）
- **URL抽出**: ユーザーが入力したURLから正規表現で11桁のIDのみを抽出。
- **形式対応**: `youtube.com/watch?v=...`, `youtu.be/...`, `youtube.com/shorts/...` 等。
- **保存**: `videos.youtube_video_id` に格納。
- **入力時同期**: URL / ID を入力した時点で、YouTube 実在確認、公開状態、動画長、サムネイルURLの軽量同期を即時試行する。成功時は「確認済み」と表示し、失敗時は理由と再試行導線を出す。
- **手動同期**: ユーザー本人は自分の作品に限り、1作品につき1日1回まで「YouTube情報を再同期」を押せる。クォータ不足や `read_only` 中は同期要求をキューに入れるだけにし、即時反映を保証しない。
- **リセット時刻**: 手動同期の1日1回制限は日本時間 0:00 にリセットする。
- **キュー再実行**: YouTube API クォータ不足でキューに入った同期要求は、翌日の日本時間 0:00 以降に自動再実行する。
- **URL種別**: Shorts URL、通常URL、共有URLはいずれも11桁の YouTube 動画 ID に正規化して保存する。
- **公開状態の扱い**: 非公開動画は「YouTube側の公開設定を確認してください」と表示する。削除済みや存在確認失敗は `youtube_sync_status = "failed"` としてユーザー修正待ちにし、`pending` へ自動で戻さない。
- **許容する動画**: プレミア公開待ち、年齢制限付き、埋め込み不可動画は投稿自体をブロックしない。埋め込み不可の場合は詳細ページ側で外部再生導線や警告を出す。
- **OGPフォールバック**: YouTube API のクォータが90%に達した場合は OGP 解析へ切り替える。取得したタイトル、サムネイル、公開予定時刻は確認・提案用に留め、ユーザー入力済みのタイトルや説明を自動上書きしない。
- **手動同期履歴**: ユーザー本人には直近1回の同期結果（成功/失敗日時と簡単な理由）のみ表示する。

### 3-4. 振り返り・アンケート項目（後日入力）
- **動的レンダリング**: イベントの `review_settings` に基づき、有効なフィールド（使用ソフト、コメント等）のみをマイページの編集画面に表示。

## 4. 詳細UIロジックとステート管理

### 4-1. 合作メンバー検索 UX
- **オートコンプリート**: `video_members` 入力時、過去の参加者リストからインクリメンタルサーチ（絞り込み表示）を行い、正確な `x_user_id` を取得できるようにします。
- **ドラッグ並び替え**: 複数メンバーがいる場合、表示順序をドラッグ＆ドロップで入れ替え可能にします。

### 4-2. アイコン画像編集
- **ブラウザ側加工**: Cloudflare にアップロードする画像はアイコン画像のみ。アップロード前にブラウザ上で `250x250px` の WebP に変換し、元ファイルが1ファイル8MBを超える場合は拒否する。
- **作品サムネイル**: 作品サムネイルはアップロードしない。YouTube URL / ID から YouTube サムネイルを取得してプレビュー表示する。

### 4-3. オートセーブと一時保存
- **ドラフト機能**: フォームの中盤に離脱した場合、入力内容を `localStorage` または D1 の `videos` テーブルに定期的に自動保存し、再訪問時にデータ損失を防ぎます。
- **復帰**: ページリロード時に「前回の続きから入力を再開しますか？」と通知。

### 4-4. 保存先確認 (active_x_user_id)
- 提出直前に、どのクリエイター名義（X ID）として作品を保存するかを確認する最終チェックモーダルを表示。
- **UI**: 「このX IDで保存しますか？」の確認モーダルを表示し、`active_x_user_id` を明示する。
- **承認待ち対応**: `approval_status == "pending"` のX IDでも下書き作成を許可する。

### 4-5. 枠（スロット）との動的紐づけ・本提出機能
- **動的紐づけ**: ページ読み込み時に、ログインユーザーの `slots` を検索し、未提出かつ確保済みの `event_id` と `slot_id` を自動でフォームの隠しフィールド（またはReadOnly表示）にセット。
- **本提出**: 「提出する」ボタン押下時に D1 の `videos` に登録。同時に `status = "pending"` (審査待ち状態) にセット。
- **所有権設定**: `owner_discord_user_id` に `session.user.id` を設定し、権限管理の基礎にする。
- **ステータス同期**: 提出完了と同時に、対応する `slots` の `status` を `"submitted"` に更新し、その `video_id` を記録。

### 4-5-1. 利用規約再同意
- 最新の利用規約へ未同意の場合、投稿・編集保存・提出の確定前に再同意画面を挟む。
- 再同意が完了するまで確定ボタンは無効化する。
- 同意後は `user_tos_consents` に記録し、元の投稿フローへ戻す。

### 4-6. 差し戻し対応の管理者フィードバック表示機能
- **役割:** 提出後に管理者から差し戻された際、理由を確認して修正できるようにする。
- **内部ロジック:** 
  - `status == "unlisted"` かつ `last_error` にコメントがある場合、フォーム上部に警告色で目立つように表示する。
  - 修正後に「再提出する」ボタンを押すと、`status` が `"pending"` (審査待ち) に戻り、再度通知が飛ぶ。

### 4-7. YouTube 連携の高度化
- URL入力時に YouTube Data API（またはOGP解析）を叩き、動画の正確な長さや非公開設定状況をチェックし、提出条件に合致しない場合にアラートを出します。
- 定期同期は6時間ごとの `youtube-sync` に任せるが、投稿直後の確認体験を損なわないよう、入力時・保存時・提出時の即時同期を優先する。
- 埋め込み不可または年齢制限で iframe 再生できない場合、動画詳細ではサムネイルと「YouTubeで視聴する」外部リンクを表示する。
