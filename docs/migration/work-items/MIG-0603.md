## Decisions (owner)
- **D-0603-1 (DECIDED 2026-10-24, Fable owner-delegate; Yugo informed after the fact): no post-commit Queue wake from `apps/api`.** CURRENT sends one `static_rebuild_available` after the batch (`staticRebuildWakeSource: "web"`); the Hono write slices persist the `static_rebuild_queue` row(s) in the same D1 batch (byte-identical UPSERT) and send **0 wakes by design**. Drain path: `flamenode-content-jobs` Recovery Cron `15 * * * *` ("static Queue wake" step) or any other producer's wake; worst case ≈ 60 min, equal to the D-11 accepted edit delay (build cadence). Correctness (permission, audit, queue row, unpublish fence) is unaffected; only public-page freshness of chapter edits during the Next/Hono coexistence window is delayed. Option (b) (Queue producer binding + wake host for `apps/api`) is deferred: decide it once, together with MIG-0614 U06 (`public_page_renders` doorbell) when the `apps/api` wrangler config is created; the wake host must live in `packages/server-core` shared with CURRENT, never a copy in `apps/api`. The binding is outward-facing and needs Yugo's explicit approval. Re-open if the owner rejects the ≤ 60 min delay at UI switch (Phase 7). Moot after MIG-0907 removes `static_rebuild_queue`. Evidence: parity test `DOCUMENTED DIFFERENCE D-0603-1` (CURRENT 1 wake / endpoint 0).
- **D-0603-2 (info): bounded event_staff read.** CURRENT reads all matching staff rows; the endpoint reads `LIMIT 100` (S2). More than 100 matching rows for <= 4 events x <= 100 approved X ids can only deny (fail closed), never grant. Not reachable with real data (<= a handful of staff rows per user).
