## Data contract (build time)
- Keys: `snapshot/event-index/current.json` (= CURRENT `events/index.json`), `snapshot/event-detail/{id}.json` (= `events/{id}.json`), `snapshot/event-release/{id}.json` (= `events/{id}/release.v1.json`). Same envelope/manifest/generation/sha256/visibility checks as every other snapshot; payloads normalized with CURRENT `staticEventsIndexCore` / `staticEventDetailCore` / `staticEventReleaseCore` (imported from `src/`, copy at Phase 9).
- Env: `FLAMENODE_SNAPSHOT_DIR`, `FLAMENODE_SNAPSHOT_MANIFEST_FILE`, `FLAMENODE_SNAPSHOT_GENERATION`. Not set -> fixtures (`eventFixtures.ts`, times fixed in 2020/2100 so output does not depend on the build date). Manifest invalid -> build fails; one object failing a check or normalizing to nothing (private, id mismatch) -> no page for that id, logged; unreadable index -> CURRENT's "公開イベント一覧を一時的に表示できません。".
- The detail payload's slot rows are used only for layout (id, time, order). Their `status` is never rendered; filled counts and names come from `GET /api/live/events/{id}/slots` in the browser.

## Island key table (`/event`, U05 / G03)
| key | value | result |
| --- | --- | --- |
| `q` | text | trimmed; case-insensitive substring of title, explanation, public operator names; also group name/description (then the group's events match) |
| `q` | empty / whitespace | no text filter |
| `status` | `all`/`open`/`upcoming`/`ended` | accepting entries / scheduled / ended; `all` shows everything |
| `status` | empty or unknown | `all` |
| `sort` | `priority`/`deadline`/`start`/`new` | CURRENT comparators (`deadline`: entry end asc; `start`: start asc; `new`: start desc; ties by upcoming priority) |
| `sort` | empty or unknown | `priority` |
| any other key | - | ignored (CURRENT reads only these three) |
Any non-default key switches to the flat "検索結果" list, as CURRENT. The server HTML is the default view; the Island re-renders from `location.search` and the clock after mount, so reload and back/forward follow the URL. Quirk kept: CURRENT normalizes a null `entry_end_time` to 0 (`Number(null)`), so `sort=deadline` puts events without a deadline first.

## Zero-slot redirect (U06 / G19)
CURRENT `slots/page.tsx` `redirect("/event/{id}")` (Next default 307). Static build: an event with no slot rows gets no `/slots` page; the Astro integration `eventRedirects` writes `/event/{id}/slots /event/{id} 307` into `dist/_redirects` (block between `# BEGIN/END generated` markers, merged with any hand-written `public/_redirects` such as MIG-0503's). Astro's own `redirects` option is not used (it emits a meta refresh, 200). Whether Workers Static Assets honors this at the Worker Route is for the gateway tasks; I did not run wrangler or any deploy.

## Parity gaps (task is not DONE)
1. `/slots` has no reservation / release / extend controls, login and terms gating, or viewer overlay (`EventSlotsViewerPanel`, RH-014). They need MIG-0604/0606. Do not cut `/event/*/slots` over before that.
2. `/event/[id]` does not render `EventRecruitCard` (recruit timeline, "full" state) or the per-event accent theme (`buildAccentVars`), and uses `icon_url` directly instead of the public X icon map projection (`resolveProjectedIcon`).
3. Clock-dependent labels (status, entry button, day metric, badges) are correct for the build instant in the HTML and refreshed in the browser; there is no scheduled rebuild at the instants where they flip, so crawlers see the build-time label.
4. `ImeSafeGetForm` composition guard is not ported; the native GET form is used (the browser already withholds Enter during IME composition in common cases).
5. Repeated query keys (`?q=a&q=b`): CURRENT reads the array form; here the first value is used.
6. Browser check at 390px / 1440px was not done in this run (no browser). Structure and classes follow `static/Events.html`, `EventDetail.html`, `EventSlots.html`, `EventRelease.html`.
7. Snapshot producers for the three event keys do not exist yet (the build uses fixtures); `/event/{id}/release` for an event without a release object is not generated (CURRENT: 404).
8. `apps/site` has no typecheck target; the site libs were verified by the tests and the Astro/Vite build only.
9. `publicDataLoader.ts` appends the event key helpers at the end of the file; sibling stacked PRs (#344, #352, #354) append there too and will conflict textually.
10. /event/[id] queue regeneration is excluded (`PAGE_BODY_FORMAT.event = "excluded"`); Island-page queue parity (Astro serializer port or AstroContainer in the consumer Worker) is an MIG-0411 follow-up (lead). After Phase 5 the consumer's production role for this kind is the unpublish DELETE + tracker close; a gateway miss stays 503 until the build (MIG-0509) provides the HTML. The MIG-0403 representative checks for the event page are re-pointed to `event/autumn-collab-2026`. See OPEN_DECISIONS.md D-11.
11. `eventData.ts` used to fall back to the fixtures when the snapshot env was only partly set; it now uses `snapshotAccessFromEnv` (a partial env throws), with a regression test.
12. `events.css` is imported by both PublicLayout and PublicPage (one stylesheet chunk for every public page). All its selectors are event-prefixed (`.ev-*`) or under the zero-specificity root `:where(.ev-scope)` (`ev-scope` is on the four event screens' `<main>`); the duplicated `.seg` blocks are merged; lint test `packages/ui/test/eventsCssScope.test.mjs`. Verified on a main build vs this build: for /recommend, /user, /list, /trending, /about and /rules every rule of main's CSS is present unchanged, and every added rule (214) is event-scoped.
