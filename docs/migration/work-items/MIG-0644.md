### Preserved semantics and unresolved U02/U03 gates

- Response from each action: `{ ok: boolean, message?: string, id?: string }`. The page discards it today; D-17-5 requires the Ops client to preserve the user-visible refresh/query behavior rather than invent a new notification.
- Validation precedence: guard first, then ID/confirmation, request type/status and shape, then transactional mutation. The legacy status updates accept `request_id` only when `id` is nullish; HTTP path supplies the ID instead. Missing/incorrect confirm remains a domain message, not a silent execute.
- Authenticated admin alone is not sufficient: same-origin write, fresh session, `xid_links` operation mode, audit actor and identity semantics must remain. Origin rejection performs no D1 read; failed validation performs no D1 writes.
- U02 must reuse existing server-core implementation without changing `packages/server-core/src/xid/**` (MIG-0618 owner); verify snapshots, CAS, restore window, queue wake and >100 X references in genuine Hono+D1 regression tests.
