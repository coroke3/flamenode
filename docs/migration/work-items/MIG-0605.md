## Owner decisions requested（S2 が CURRENT より厳しい上限を強いるもの）
- SP-1 page size: CURRENT は既定 500 行（ADMIN_SPREADSHEET_PAGE_SIZE、上限 5000）。S2 は LIMIT 100 以下・応答 64 KiB 以下のため MAX_SPREADSHEET_PAGE_ROWS = 50（既定かつ上限。tables 応答の pageSize もこの値）。grid UI は 50 行で paging する。代案は 99。
- SP-2 export: CURRENT は最大 5000 行。今回は MAX_SPREADSHEET_EXPORT_ROWS = 99 行かつ 48 KiB で、超えると partial（X-Spreadsheet-Truncated: 1、ファイル名 -partial。CURRENT に既にある partial 表現）。全件 export は (a) partial を許容 (b) offset / cursor 引数を追加（新しい API）(c) Queue + R2 の非同期 export job のどれかをオーナーが決める。
- SP-3 幅広い行: 行データ 48 KiB の上限は行ごと落とし（セルは切らないので inline 編集で値が壊れない）、truncated: true と hasMore: true を返す。events の JSON 列（最大 100 KB）のような巨大セルのテーブルは SP-1 の行数を下回る。代案はセル単位の切り詰め + 読み取り専用 marker（編集契約が変わる）。
- SP-4 発見（対応不要）: CURRENT discovery.ts は sqlite_master 内で `pragma_table_info(name)` を使うが、SQLite 3.50（node:sqlite）は name を関数自身の列に解決して 0 件になる。こちらは `sqlite_master.name` と修飾した。テストの参照側 connection も同じ書き換えで CURRENT の実コードを動かす。Remote D1 では未検証（remote 操作なし）。
- SP-5 エラー文言: CURRENT は想定外の D1 エラーで生の message を 500 で返していたが、本 PR は固定の { error: "internal_error" }（adminRead と同じ方針、SQL/テーブル名を出さない）。unknown_table 400 と db_unavailable 503 は CURRENT の code のまま。404 disabled・400 を含め全応答に private no-store を付ける（CURRENT は成功時のみ）。
- SP-6 運用: cutover 前に Worker に ADMIN_SPREADSHEET_ENABLED var（secret ではない）が必要。設定は Cloudflare 操作のためオーナー実施で、今回は未実施。
