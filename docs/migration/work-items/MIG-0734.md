## 2026-11-04 JSON 401 write-guard regression fix

- Review finding: `apps/api/src/middleware/writeOrigin.ts#writeGuardDenyBody` returns `{ok:false,reason:"unauthenticated",message}` with HTTP 401. Shared `apps/ops/src/api/write.ts#send` reports JSON bodies containing a boolean `ok` as `status:"ok"` even for HTTP 401. Previously `toWriteResult` lost the session-expired signal and the admin mutation UI did not redirect to `/entry`.
- Fixed only the owned `apps/ops/src/api/adminCostGuard.ts#toWriteResult`: treat a parsed `{ok:false,reason:"unauthenticated"}` as `anonymous:true` while preserving the server message. Both Cost Guard and Notification clients share this adapter. Other write-guard denials (403/409) still surface their message and do not redirect.
- Regression test: `apps/ops/test/adminOps.test.mjs` now exercises actual Hono-shaped JSON 401 for both cost-guard and notification writes and verifies `leaveWhenAnonymous()` routes to `/entry`, in addition to the existing 401 body-without-ok case.
