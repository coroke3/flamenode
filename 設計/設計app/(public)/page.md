# TOPページ設計 (`/`)

## 1. 概要
FlameNodeの総合窓口となるランディングページです。旧アーカイブサイトとしての役割（過去の動画・イベントへの誘導）と、プラットフォームとしての役割（現在開催中のイベント告知・ダッシュボードへの導線）を併せ持ちます。

## 2. デザイン方針

- **コンセプト**: 旧 EventArchives トップの「高コントラスト・横スクロール作品棚・丸いクリエイターアイコン・高密度イベントカード」をベースにし、FlameNode のイベント参加機能と X ID 主体切替を加える。黒基調そのものへ必ず準拠せず、ライト/ダーク両方のテーマで同じ配置密度を再現する。
- **レイアウト**:
  - **上部**: 大きな文字だけで画面を占有しない。開催中イベント、注目作品、おすすめ導線をコンパクトな情報帯として横並びまたは2段で配置し、ファーストビュー内に作品カードが見えるようにする。
    - **募集イベントあり**: 参加導線を表示するが、巨大な告知面にはしない。イベント名、締切、スロット確保ボタン、注目作品を同じ視界に入れる。
    - **募集イベントなし**: アーカイブ視聴に集中し、検索・作品一覧・おすすめ作品への導線を短く置く。
  - **中部〜下部**: おすすめ作品、最新イベント、クリエイター等のセクションが垂直に並び、各セクション内は水平スクロール可能なカードスライダー形式（NetflixやPrime Videoのホーム画面のリファレンス）。
- **視覚演出**: 背景演出より作品サムネイルの密度を優先する。装飾グラデーションは使う場合もごく薄くし、作品がページ背景へ直接並ぶ印象をライト/ダーク双方で守る。
- **ライト/ダークモード**: `FlameNode-Design-System.md` のトークンに従い、ライトではカード境界と影、ダークでは背景差とスポットライト効果で作品カードを引き立てます。
- **体験**: 
  - **未ログイン時**: FlameNodeのビジョンと「まずはここから」というガイド的な動線を提示。
  - **ログインユーザー**: 「前回の続き（自身の提出状況）」を上部情報帯に統合した `SlotStatusCard` で即座に確認できるパーソナライズされた体験を提供します。

## 3. 目次・機能一覧

1. **上部導入帯機能**: 募集イベントの有無による表示切り替え。巨大ヒーローではなく、作品棚を押し下げない短い導入帯として扱う。
2. **おすすめ作品表示機能**: スコア上位のアーカイブ作品のランダム表示
3. **ピックアップクリエイター表示機能**: 複数作品に参加しているクリエイター（個人1作以上、または合作参加2作以上）の抽出表示
4. **最新作品表示機能**: 登録された最新の公開作品リスト表示
5. **最新イベント表示機能**: 直近のイベントと、それに属する作品のネスト表示

## 3-1. 配置再現の基本仕様

- 旧 EventArchives トップの視覚構成をベースにする。公開 UI の正式ロゴと文言は FlameNode に置き換えるが、横スクロール棚、中央寄せのセクション見出し、右側の「もっと見る」、半透明の丸矢印、サムネイル中心の作品カードという骨格は維持する。色はライト/ダークのテーマトークンを正とする。
- 配置順は、コンパクトな開催中/注目エリア、おすすめ作品、クリエイター、最新作品、イベントの順を基本とする。
- 各作品カードはサムネイル、作品名、クリエイターアイコン、クリエイター名を必須表示する。
- 作品カードのサムネイルは YouTube サムネイルを利用し、Cloudflare/R2 へ作品サムネイルを保存しない。
- おすすめ作品は `video_score` 上位 40 件程度を候補化し、表示時にシャッフルして毎回違う出会いを作る。
- おすすめ候補には `x_reapply_required`, `voided`, 非公開、手動非表示の作品を含めない。`video_score` は FlameNode 内閲覧数だけでなく、正規化した YouTube 側再生数も含める。
- おすすめクリエイターは「個人作品 1 件以上」または「合作参加 2 件以上」の条件を満たす X ID から抽出する。
- 最新イベントは直近 3 件を表示し、各イベントに最大 8 作品をネストして表示する。

## 3-1-1. 旧資料不要のトップ完成イメージ

旧ページ資料がなくても再現できるよう、トップページの完成形を次のように固定する。

- **ファーストビュー**: ヘッダーの下に短い導入帯を置き、その直下に「おすすめ」セクションの見出しまたは作品カードの上端が見える。導入帯だけで画面を埋めない。
- **導入帯**: デスクトップでは幅 `80%` から `90%`、最大幅 `1200px` から `1280px`、高さ `180px` から `250px`。中央に `FlameNode`、下に1行説明を置く。募集イベントがある場合は右側または下段に参加 CTA、締切、空き枠情報、注目作品1から3件を差し込む。
- **セクション見出し**: 見出しは中央寄せで `24px` から `30px`、太字。下線は幅 `48px` から `80px`、高さ `1px`。`もっと見る` は同じセクション行の右端に `13px` から `15px` で置く。
- **作品棚**: 作品棚は画面幅いっぱいに近い横スクロール。中央コンテナ内に閉じ込めず、左右端の作品が少し切れて見えてもよい。棚の左右端にはフェードを置く。
- **作品カード**: デスクトップは幅 `250px` から `300px`、サムネイル比率 `16:9`、タイトル2行、作者行1行。カード間 gap は `20px` から `28px`。カード背景は透明を基本にする。
- **2行棚**: モバイルと幅の狭いタブレットでは、作品棚を2行にして表示密度を上げる。2行目は半カード分だけ右へずらして、単調な格子に見えないようにする。
- **矢印**: PC の左右矢印は直径 `44px` から `52px`、棚の左右端から `64px` から `96px` の位置に重ねる。モバイルは直径 `30px` から `34px`。絵文字ではなく Font Awesome などの矢印アイコンを使う。
- **クリエイター棚**: 丸アイコンを主役にし、デスクトップは直径 `72px` から `88px`、モバイルは `56px` から `64px`。名前はアイコン下1行。作品数などは必要時だけ小さく出す。
- **イベントカード**: イベントカードは1イベントごとに横長の低いパネルとして表示し、上部にイベントアイコン `40px`、イベント名、開催状態を置く。内部には小型作品カードを最大8件、デスクトップ4列前後、モバイル2列で並べる。
- **テーマ差分**: ライト/ダークで変わるのは色と境界線だけ。カード数、棚幅、見出し位置、矢印位置、余白量は同じにする。
- **禁止事項**: ファーストビューを巨大なロゴ、巨大な説明文、単独のブランドコピーだけで埋めない。作品サムネイルより装飾背景を目立たせない。絵文字をアイコン代わりに使わない。

## 3-2. 詳細配置仕様

### ページ全体
- コンテンツ最大幅は `1400px`、中央寄せ。左右余白は通常 `16px`、幅 1400px 未満ではセクション幅を約 `96%` にする。
- トップは縦方向に「開催中/注目エリア」「おすすめ」「クリエイター」「最新の作品」「イベント」を積む。
- セクション間隔はデスクトップで `48px` 前後、モバイルで `16px` から `24px` 前後に詰める。
- 公開ページは表示数を優先し、大きなカード枠や過剰な余白を使わない。カードはサムネイルとテキストが直接並ぶ軽い見え方を基本にする。
- ダークモードでは深い背景、ライトモードでは白基調を使う。どちらも同じ配置密度を保ち、セクションの余白には背景色の差を作りすぎない。

### 開催中/注目エリア
- ページ先頭に置くが、上下余白は `20px` から `32px` 程度に抑える。
- 見出しはデスクトップで `28px` から `34px` 程度、モバイルで `22px` 前後にする。
- FlameNode の説明文は1から2行に留め、作品カードやイベント導線を押し下げない。
- 募集中イベントがある場合は、イベント名、開催状態、参加 CTA、空き枠状況、注目作品1から3件を同じ帯の中に置く。募集がない場合は、おすすめ作品、検索、作品一覧への導線を置く。
- 旧ページの中央タイトル面を参照する場合でも、導入帯はデスクトップで高さ `180px` から `250px` 程度、モバイルで `150px` 前後を上限にする。中央に FlameNode 名、下に短い説明を置き、画面下端に次の「おすすめ」見出しまたは作品棚が見え始めるようにする。
- 導入帯は画面幅いっぱいの巨大な告知画像にはせず、テーマ背景に自然に馴染む控えめな面として扱う。募集イベントがある場合はイベント CTA と注目作品を導入帯内に同居させ、文字だけの面にしない。

### セクションヘッダー
- セクションタイトルは中央寄せ寄りに置き、デスクトップで `28px` 前後、モバイルで `24px` 前後。
- 「もっと見る」は右寄せ。広い画面ではコンテンツ最大幅の右端、狭い画面では右端 `3%` 付近へ寄せる。
- タイトルと「もっと見る」は同じ高さに置くが、モバイルでは「もっと見る」を小さくしてタイトルの邪魔をしない。
- タイトル下へ短い白線またはテーマ色の細線を置く。線は `40px` から `80px` 程度に留め、見出しを過剰に飾らない。

### 横スクロールスライダー
- 各スライダーはブラウザ幅いっぱいに広げる。中央コンテナ内だけで切らず、左右にグラデーションフェードを置く。
- スクロール本体は横並び、gap はデスクトップ `24px`、モバイル `8px`。
- スクロールバーは基本非表示。PC では左右の丸い矢印ボタンを出す。
- 左右矢印は `48px` の円形、モバイルは `30px`。左右端からデスクトップ `80px`、モバイル `20px` 程度。
- 自動スクロールを標準採用し、同じアイテム群を3回分連結して疑似的な無限スクロールにする。ホバー、フォーカス、タッチ、ドラッグ、矢印操作中は自動スクロールを止め、操作終了後にゆっくり再開する。
- モバイルでは2行の横スクロールにし、2行目をカード半分程度右へずらすことで密度と動きを出す。
- 旧ページ再現として、矢印は半透明の円形ボタンにする。ダークモードでは暗色面に明色矢印、ライトモードでは明色面に濃色矢印を置く。
- 棚の左右端にはフェードを置き、画面外にも作品が続いていることを示す。フェードはカードを隠しすぎず、端のサムネイルが半分見える程度を許容する。

### 作品カード
- デスクトップ幅は `280px`、モバイル幅は `150px` から `220px`。
- サムネイルは必ず `16:9`、角丸 `8px` 以下、object-fit cover。
- ホバー時はサムネイルを `1.05` 程度に拡大し、カード全体は `-3px` から `-5px` 程度上へ動かす。
- タイトルは2行まで。デスクトップ `16px` 前後、モバイル `12px` から `13px`。長いタイトルは省略する。
- 作者行はアイコン `24px`、名前 `14px` 前後。モバイルではアイコン `15px`、名前 `10px` 前後まで詰める。
- 状態バッジやおすすめバッジはサムネイル右上に置き、カード本文の高さを増やさない。
- カード背景は原則透明にし、サムネイルと文字がページ背景へ直接置かれる見え方にする。ライト/ダークとも必要最小限の hover 背景だけを使う。
- 作品タイトルは白または濃色で強く、作者名は一段小さくする。サムネイル下の余白は短く、1画面あたりの表示数を増やす。

### クリエイターカード
- デスクトップ幅は `180px`、モバイル幅は `100px` から `140px`。
- アイコンはデスクトップ `80px` 円形、モバイル `60px` 円形。
- 名前は1行省略。作品数や推薦理由は小さく、必要な場合のみ表示する。
- クリエイタースライダーは、トップの中で作品スライダーと同じ横スクロール構造を使う。
- 旧ページの丸アイコン列をベースにし、アイコン未設定時はテーマに応じたプレースホルダー円を表示する。名前はアイコン下に中央寄せで置く。

### イベントセクション
- イベント一覧はカード型グリッド。デスクトップでは `minmax(400px, 1fr)`、モバイルでは1列。
- イベントカードの中に、アイコン `40px`、イベントタイトル、最大8件の小型作品グリッドを置く。
- イベント内作品カードは `minmax(160px, 1fr)`、モバイルは `120px` 目安または2列。
- 公式イベントと第三者イベントの見た目は同じ。代表者と運営メンバーはイベント詳細で確認できるようにする。
- `events.accent_color` がある場合、イベントタイトルの下線、開催中バッジ、参加 CTA、ホバー線にその色を使う。
- 旧ページのイベントカードのように、低い角丸パネル内へイベント名と小型作品グリッドを詰める。パネル色はテーマトークンに従う。パネルの余白は `20px` 前後、作品グリッドの gap は `16px` 程度にし、1イベント内の作品数が視認できることを優先する。

## 4. 各機能の詳細解説

### 1. 上部導入帯・パーソナルダッシュボード機能

- **役割**: 短いブランド導入、およびログイン中ユーザーのアカウント状態（イベント参加状況等）に応じたアクションの提示。巨大ヒーローではなく、旧ページのトップ面を圧縮した導入帯として扱う。
- **データ取得・判定**:
  - `events` テーブルから `is_active == true` のイベントを判定。
  - ログイン機能および `user` テーブルから現在のユーザーのログイン状況と、対象イベントへの参加（受付）状況を取得。
- **振る舞い**:
  - **未ログイン時**: FlameNodeの案内と「ログイン／新規登録」への誘導。
  - **募集イベントあり**:
    - **ログイン済・イベント参加「未確保」時**: 開催中イベントのバナーと、目立つ「スロットを確保する」ボタンを表示。
  - **ログイン済・スロット「確保済」時**: 上部情報帯に `SlotStatusCard` をマウント。現在確保している特定の枠情報と、「動画を提出する」へのダイレクトアクションを表示。
    - **投稿済み・審査中**: ステータスが `pending` になり、運営からのフィードバック待ちであることを通知。
  - **募集イベントなし**:
    - **アーカイブ集中レイアウト**: 過去の名作/人気作を中心に表示し、検索や一覧への導線を最上部に配置。
    - **イベント履歴導線**: イベント一覧や過去イベント詳細へのリンクを強める。

### 2. おすすめ作品表示機能

- **役割**: 過去の良質な作品をピックアップし、スクロール可能なスライダーで表示する機能。
- **データ取得**: `videos` テーブルから `status == "public"` かつ `is_deleted == false` のものを取得。
- **内部ロジック**: `video_score` が上位の作品を抽出し、毎回異なる作品と出会えるようにランダム（シャッフル）して表示する。
- **抽出詳細**:
  - まず `video_score` 降順で上位40件を候補化する。
  - 表示時にシャッフルし、同一作者の作品が連続しすぎる場合は間に別作者を挟む。
  - 候補が少ない場合は最新公開作品で補完する。
- **UI要素**: 作品のサムネイル、タイトル、クリエイターアイコンと名前を表示し、クリックで動画詳細（`/[id]`）へ遷移。
  - **既存再現**: カードには必ずクリエイターのアイコンと名前のペアを含める。

### 3. ピックアップ・おすすめクリエイター表示機能

- **役割**: ユーザーに新たな交流や出会いを提供するスライダー表示。個人の状況によってレコメンド内容を動的に変化させる。
- **データ集計・表示ロジック**:
  - **ログイン済時（パーソナライズレコメンド）**: 過去に評価（いいね・マイリスト等）した作品の作者、過去に合作したクリエイター、または自分と似た作風・使用編集ソフトのクリエイターを優先的に抽出・レコメンドする。
  - **未ログイン時（フォールバック）**: 継続参加している注目クリエイターからランダムピックアップ。
    - **抽出ロジック**: 「個人作品が1つ以上」または「合作参加作品が2つ以上」の条件を満たすユーザーから最大40名をランダムに選出。
- **UI要素**: クリエイターアイコン・名前のほか、ログインユーザーに対して「なぜおすすめされたか（例：よく見ているクリエイター、過去の合作メンバー等）」が分かるラベルを表示。クリックでプロフィール（`/user/[id]`）へ遷移。

### 4. 最新作品表示機能

- **役割**: プラットフォームに登録された、最新の公開作品の一覧スライダー。
- **データ取得**: `videos` テーブルを `scheduled_time` の降順で取得（最新30件）。
- **UI要素**: 「おすすめ作品」と同様のカードコンポーネントを使用し、詳細へリンクする。

### 5. 最新イベント表示機能

- **役割**: 直近に開催された3つのイベントと、そのイベントで投稿された作品群を一覧化するグリッド表示。
- **データ取得**: `events` テーブルから最新3件を取得後、`video_events` 経由で紐づく `videos` (各最大8件) をネストして取得する。
- **UI要素**: イベントのヘッダー（アイコン＋タイトル）の下に、属する作品が小さなグリッドで並ぶ構成。イベントタイトルクリックで `/event/[id]` へ遷移。

## 5. 詳細UIロジックとステート管理

### 4-1. ローディング・初期表示 (Skeleton UI)
- データの読込完了まで、スライダーおよびイベントグリッドの形状を模した**スケルトンカード**を表示します。
- スケルトンにはシマー（光が流れるような）アニメーションを付与し、UXの停滞感を防ぎます。

### 4-2. スライダーのインタラクション
- 横スクロールには `Snap Scrolling` を採用し、スマートフォンでも滑らかにカード単位でピタッと止まるように調整します。
- PC ではスクロール矢印を常時表示し、クリックによる手動介入を可能にします。ホバー時は矢印の濃度を上げる。
- PC では自動横スクロールを標準動作にする。ユーザーがホバー、タッチ、ドラッグ、矢印操作をした場合は一時停止する。
- モバイルでは2行レイアウトを優先しつつ、自動スクロールも維持する。ユーザーがスワイプした場合は手動操作を優先して一時停止する。

### 4-3. エラーハンドリング
- D1からのデータ取得に失敗した場合、またはデータが空の場合、各セクションごとに「現在作品の読み込みに失敗しました」というメッセージと共に、再試行ボタン、またはアーカイブ全体へのリンクをフォールバックとして提示します。

### 4-4. SEO・メタデータ
- サーバーサイド (RSC) で取得した最新のイベント情報、またはおすすめ作品のタイトルを `og:description` 等に動的に埋め込み、シェア時のリッチ度を最大化します。
