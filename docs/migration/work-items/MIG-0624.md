## Decisions
- Status mapping of CURRENT redirects: not logged in -> 401 (`{error:"Unauthorized"}`); banned -> 403 (`requireAuth`, `User is banned`); neither admin nor event staff (CURRENT layout `redirect("/dashboard")`) -> 403 `{error:"Forbidden", reason:"manage_access_required"}`, applied to every endpoint before the page-level check; CURRENT `notFound()` (unknown event, no permission on the event, `event.slots` missing on slots) -> 404 `{error:"Not Found"}`; D1 failure -> 503 `{error:"unavailable"}`. Every response is `Cache-Control: private, no-store`.
- Authorization is the same as CURRENT: approved linked X ids -> `event_staff` rows -> preset / custom keys (legacy aliases via `@flamenode/domain/auth/permissions`) -> per-event permission union; admin bypasses. The preset table is copied (`PRESET_PERMISSIONS`) and asserted equal to CURRENT `PRESET_DEFINITIONS`. Staff page: any permission opens it read-only, `event.members` enables member management (`canManageMembers`). Slots page: `event.slots`. The authorization snapshot is rebuilt on every request (removed staff / unapproved X lose access on the next request).
- No page-load write exists in these four CURRENT pages, so there is no handoff to MIG-0702 from them.
- ZERO_1102 S2: LIMIT constants `MAX_STAFF_ROWS`=100, `MAX_MANAGE_EVENTS`=100, `MAX_INBOX_ROWS`=20, `MAX_NOTIFICATION_ROWS`=20, `MAX_MANAGE_LINKED_X`=100, `MAX_STAFF_MEMBERS`=100, `MAX_SLOT_ROWS`=100; each JSON column is parsed at <= 64 KiB (larger -> 503); responses asserted <= 64 KiB. Ids are always bound parameters.
- Deviation (S2 cap): CURRENT lists every event / 500 slots. The API returns at most 100 events (`truncated` / `eventsTruncated`, also set when a user has > 100 staff rows) and 100 slots per request; slots 101..500 are read with `?offset=` (0..400, clamped). Slot order gets an extra `id ASC` tiebreak so pages are stable.
- Deviation (icon signing): CURRENT signs internal X icons with `AUTH_SECRET` (`resolveManageXIconUrl`). The API has no signing key, so staff `icon_url` is the external https URL or null. Handoff: provide the signing key to the API (secret binding, needs explicit approval) or sign in the SPA backend before MIG-0704 ships the staff page.
- Deviation (notifications row): only the columns `NotificationOutboxSummary` renders are returned (no `lease_token`, `processing_started_at`, ...). A read failure of the notification section (missing `event_id` column CURRENT warns about, or an oversize JSON column) degrades like CURRENT: `notificationSchemaMissing: true`, empty list.
- Known gap: `ManageActiveXNotice` input `activeXUserId` is resolved with CURRENT `resolveActiveXUserId` from the user's linked X rows (one extra JSON column, no extra statement); admins get null (CURRENT does not render the notice for admins).
- Known gap: ties in `roleByEvent` between two equal-priority staff rows depend on row order in CURRENT (undefined) and in the API (D1 order); inbox / notification ties get `id DESC` (CURRENT unordered).
