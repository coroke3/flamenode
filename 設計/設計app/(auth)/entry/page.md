# エントリー（受付）ページ設計 (`/entry`)

## 2. デザイン方針

- **コンセプト**: "Welcome to the Celebration" (祭典への招待)
- **レイアウト**:
  - **全体**: 画面中央に配置されたモーダル状のステップカード。
  - **フロー**: 「規約確認」→「アカウント連携確認」→「イベント参加枠（スロット）選択」の3ステップ。最新規約への同意が必要な場合は投稿・提出時に再同意を求める。
  - **ナビゲーション**: 上部に現在の進捗を示すシームレスなプログレスバーを常駐。
- **視覚演出**: `FlameNode-Design-System.md` の方針に従い、各ステップの遷移時には控えめなガラス質感と黄色アクセントを採用。背景にはイベントのキービジュアルをアンビエント照明として薄く投影します。
- **体験**: スロット選択時は、空き状況が分かる予約表 UI を提供し、クリック一つで枠の確保を完了させます。

## 3. 目次・機能一覧

1. **利用規約（TOS）確認・初回同意機能**: 法的・運営上のルールへの同意取得
1. **受付ステータス判定機能**: 運営による受付開始・停止のリアルタイム反映
1. **表示名（display_name）設定機能**: お祭りで公開される名前の登録（必須）
1. **ダブルブッキング防止・枠確保機能**: トランザクションを用いた確実な予約
1. **アカウント連携確認機能**: Discord/X IDのステータス表示

## 3. 各機能の詳細解説

### 1. 利用規約（TOS）確認機能

- **役割:** 参加後のトラブルを防ぐため、ルールへの承諾を記録する。
- **仕様:**
  - スクロール可能なエリアに規約全文を表示。
  - 初回エントリー時は同意チェックを表示し、同意ボタン押下時に `user_tos_consents` と `user.accepted_terms_version_id` を更新する。
  - 規約更新後の再同意は、次回作品投稿、作品編集保存、提出時に要求する。スロット確保だけでは原則ブロックしない。

### 2. 受付ステータス判定機能

- **役割:** 運営が手動で受付を停止した場合に、ユーザーが操作できないようにガードする。
- **内部ロジック:** `events` テーブルの `is_active` または `is_entry_open` が `0` (False) の場合、ページ全体をモーダルで覆い、「現在、受付は停止されています」というメッセージを表示する。

### 3. ダブルブッキング防止・枠確保機能

- **役割:** 同時刻に複数のユーザーが同じスロットを予約しようとした際、一人だけが成功するように制御する。
- **実装（サーバーサイド）:**
  - **CAS (Compare-And-Swap) パターン**を使用（`TECHNICAL_SPEC.md §3.1` 参照）。
  - 1. `UPDATE slots SET discord_user_id = :userId, x_user_id = :activeXUserId, display_name = :displayName, status = 'reserved' WHERE id = :slotId AND status = 'available';` を実行。
  - 2. `rowsAffected` が 1 であれば成功。0 であれば他者が先に確保したと判断し、ユーザーに「この枠は直前に予約されました。別の枠を選択してください」等の警告を出す。

### 4. アカウント連携確認機能

- **役割:** ログイン中のDiscord IDが正しいかを確認させる。
- **仕様:** 連携済みのDiscord名（`Name`）を表示。X IDの連携は任意だが、推奨メッセージを表示する。
- **承認待ち対応:** X IDが承認待ち（`approval_status == "pending"`）でも、スロット確保や下書き作成はブロックしない。ただし「選択中の X ID が運営により却下された場合、受付中イベントの未提出枠は自動的に解放されます。終了済み・募集終了済みの企画枠は履歴として保持されます」という警告を常設し、チェック確認または目立つアラートで事前告知する。提出済み作品がある場合は `x_reapply_required` として保持し、枠取り直しを先に案内する。

## 4. 詳細UIロジックとステート管理

### 4-1. 遷移ガード (Auth Integration)

- **仕様**: このページは `(auth)` グループ内にあり、Discordログインがない場合は自動的にサインイン画面へリダイレクトされます。さらに、一度エントリーが完了している（既にスロットを持っている）ユーザーがアクセスした場合は、自動的にダッシュボード (`/dashboard`) へ誘導します。

### 4-2. スロット選択UI

- **ビジュアル**: 時間に紐付くスロットは、ホットペッパービューティー風に時間と空き状況（○ / ×）が1対1で見える表で表示する。
- **時間なしスロット**: 番号またはラベルと空き状況だけを見せる簡易リストにする。
- **連続枠**: イベントごとの最大連続取得数まで、連続する空き枠をまとめて取得できる。既定は最大3枠。
- **複数枠の代表時刻**: 連続枠を取得した場合、作品側の `scheduled_time` は最初の枠の `start_time` を正とする。連続していない枠の同時取得は許可しない。
- **代理確保**: 管理者と当該イベントのイベント編集許可者は、必要に応じてユーザーの枠を代理確保できる。操作は `history_logs` に残す。
- **再取得猶予**: X ID 却下に伴って解放された元枠は24時間だけ元投稿者へ優先再取得候補として提示する。公開ページでは承認待ちや却下状態は出さない。
- **リアルタイム反映**: 持続的接続を行わず、SWR等を用いた短周期ポーリングで、他者が予約したスロットが即座にグレーアウトされるように実装します。
