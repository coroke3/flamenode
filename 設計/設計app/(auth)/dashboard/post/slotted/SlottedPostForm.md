# 枠あり投稿フォーム部品設計 (`SlottedPostForm`)

## 1. 役割
予約済みスロットに紐づく作品情報を入力・提出するフォーム部品。

## 2. 入力
- スロット ID
- アクティブ X ID
- 作品タイトル
- YouTube URL または ID
- 作者表示名、楽曲、クレジット、コメント、メンバー、使用編集ソフト
- イベント固有質問

## 3. バリデーション
- スロット所有者とログインユーザーを照合する。
- アクティブ X ID が作品主体として利用できるか確認する。
- スロットの `x_user_id` がアクティブ X ID と一致するか確認する。承認待ち X ID は許可するが、却下時に受付中イベントの未提出枠が自動解放され、終了済み・募集終了済みの枠は履歴保持される警告を表示する。
- 作品が `x_reapply_required` の場合、通常提出ボタンより先に枠取り直し導線を表示する。枠取り直しと X ID 再申請は1つのウィザードで扱い、最初のステップは枠の再取得にする。
- `x_reapply_required` では再申請期限7日を明示する。期限切れ、または受付終了までに枠取り直しが完了しない場合は `voided` になることを表示する。
- 元枠の24時間優先再取得が残っている場合は、その枠を上位表示する。元枠が取れない場合は代替枠を提示し、なければ空状態を出す。
- YouTube ID は 11 桁の動画 ID に正規化する。
- YouTube URL / ID 入力時に即時同期を試行し、動画の存在、公開状態、サムネイルURLを確認する。
- 最新の利用規約へ未同意の場合は提出前に再同意を求める。
- 作品サムネイルはアップロードせず、YouTube サムネイルをプレビューに使う。

## 4. 出力
- 保存後は `videos` と `slots.video_id` を疎結合で紐づけ、単枠なら対象枠、連続枠なら `reservation_group_id` が同じ枠群の最初の `start_time` を `scheduled_time` として作品側へコピーする。
- 枠取り直し完了後、旧 `reservation_group_id` は引き継がない。旧枠と新枠の関係は `history_logs` に残し、管理者だけが確認できるようにする。
