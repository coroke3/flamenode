# Phase 8: DB整理・旧データ・通知・Worker・危険操作

## 目的

DBの正データ/キャッシュ/履歴/未実装/将来機能を整理し、旧データ取り込み・通知・Worker・危険操作・監査ログを安全に扱う。

## 推奨モデル

- 実装: Sonnet
- migration、破壊的変更、旧データ大量更新、復元設計: Opus

## 対応要求ID

J-1〜J-17、K-1〜K-5、L-1〜L-6、M-1〜M-5、P-1〜P-6、Q-1〜Q-6、N-1〜N-6

## DB整理

- `video_comments` はdeprecated扱い。新規利用しない。
- チャプター種別カラムはMVPでは固定値または削除候補。
- `outro_comment` と `closing_comment` は統一する。
- X ID再申請情報・無効化情報は当面作品本体に保持してよい。
- スロット表示名は基本的に作品情報の活動名へ同期。提出前は仮名保持可。
- 自由HTML/CSS機能はMVPから外さない。独自タグ・ショートコード・サニタイズで安全に設計。
- プロフィールページは構造化ブロックだけに限定しない。
- APIキー管理は作る。スコープ、レート制限、有効期限を含める。
- 使用ソフト辞書は既存データを元に選択式へ寄せる。
- コスト使用量履歴は残すが、それ自体が無料枠を消費しすぎないようバランスを取る。
- ダッシュボード集計キャッシュは更新経路がある場合のみ使う。
- `system_settings` はglobal 1行。
- 削除は論理削除・アーカイブ優先。

## イベント所属

- 複数イベント所属欄に所属する全イベントを保存。
- その中から1つ、枠・上映上の所属イベントを主イベントとして扱う。
- 主イベントは所属イベントの中から1つ選ぶ。
- 主イベントが所属イベント一覧に含まれていない状態を禁止。
- `/admin/health` で不整合を検出。

## 旧データ取り込み

- 管理者専用の危険操作。
- 実行前に必ずDry Run。
- 作成・更新・スキップ・エラー件数を表示。
- ファイルサイズ・件数制限を設ける。
- 旧データ由来X IDは通常X IDと大きく分けない。
- 本人編集権限はDiscord連携・承認状態に基づいて安全判定。
- 差分表示を行う。

## 通知

- 通知は各処理から直接送らず、通知キューに積む。
- 対象: X ID申請、承認/却下、作品提出、承認/却下、修正依頼、規約再同意、CostGuard変更。
- Discord通知だけでなくサイト内通知も用意。
- サイト内通知はDiscordと同等内容。
- 通知失敗時は再試行・失敗履歴を管理画面で見られるようにする。
- イベント運営者向け受信箱を作る。

## Worker・静的JSON

- 実装済み・未実装・設計のみをMarkdownで整理。
- 対象: 静的JSON生成、YouTube同期、スコア再計算、期限切れ処理、通知Dispatcher。
- 実装済みのものだけデプロイ手順に載せる。
- 未実装のものは設計メモとして分離。

## 危険操作・監査ログ

- 削除、無効化、却下、一括操作は危険操作。
- 共通モーダルを使い、影響件数を表示。
- 必要に応じて確認文字列を要求。
- 重要操作はすべて監査ログに残す。
- 監査ログはJSONそのままではなく、変更前後の差分として表示。
- 物理削除は要再検討。
- historyに差分を保存して復元できる設計を前提。
- 復元機能未実装の間は、イベント・作品・ユーザー関連データの破壊的削除を制限。

## 管理画面・運営画面UX

- 管理トップは「今日やること」を最初に表示。
- 審査待ち作品、X ID申請、修正依頼、期限切れ候補をキュー化。
- イベント管理画面に基本情報、受付、枠、権限、公開プレビューの準備チェックを出す。
- 作品・イベント・X ID詳細では編集フォームより先に状態カードを出す。
- 管理画面はテーブルだけでなく、カード、フィルタ、要対応表示を組み合わせる。
- モバイル管理も最低限操作できる。
