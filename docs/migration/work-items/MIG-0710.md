## 2026-11-09 D-16-2 HTTP status / JSON body contradiction hardening

- Shared Personal SPA `send()` could previously return `{status:'ok', data:{ok:true}}` for HTTP 4xx/5xx, or for HTTP 401 with misleading success-shaped JSON. In a terms acceptance form, that could show a false success / trigger a refresh. API authorization is independent, but the client must not claim completion on transport failure.
- `apps/app/src/api/write.ts` now treats HTTP 401 as `anonymous`, rejects success-shaped HTTP errors as `unavailable`, and still preserves explicit `{ok:false,message}` API denials (including HTTP 409) so the UI can display the service's message.
