# イベント管理部品設計 (`EventsManagement`)

## 1. 役割
イベント作成、基本情報編集、スロット生成、カスタム質問、編集可能フィールド、削除権限、イベント編集許可者、イベント協力者、運営メンバー公開範囲、イベントアクセントカラー、イベントグループ、アーカイブを扱う管理部品。

## 2. 権限
- 管理者は全イベントを操作できる。
- イベント編集許可者は許可されたイベントのみ編集でき、担当イベント内の作品内容も編集できる。
- 協力者はイベント単位で付与された `permission_key` に一致する機能のみ操作できる。本人承認は不要。

## 3. 操作
- イベントタイトル、説明、外部画像URLまたは旧データ由来画像URL、開催期間、受付状態、イベントグループ、アーカイブ状態を編集する。
- イベントアクセントカラーは HEX 入力で設定し、視認性が悪い場合は警告する。
- 代表者と運営メンバーは、公開ページに表示するメンバーと管理画面だけで見えるメンバーに分ける。
- スロットの一括生成、空き枠公開、確保状況確認を行う。
- 時間ありスロットは、時間と空き状況（○ / ×）が1対1で見える予約表 UI にする。時間なしスロットは、番号またはラベルと空き状況だけを見せる簡易リストにする。
- 連続枠取得に対応し、最大連続取得数はイベントごとに設定する。
- 管理者と当該イベントのイベント編集許可者は、ユーザーの代理で枠を確保できる。代理確保、X ID 却下による枠解放、24時間優先再取得、枠取り直し完了は `history_logs` に残す。
- X ID 却下後に枠を取り直す場合、新しい予約へ元の `reservation_group_id` は引き継がない。旧枠との関連は管理者向け履歴だけで確認する。
- 優先再取得中の元枠は、一般ユーザーには「選択不可の空き（確保処理中）」として表示し、「この枠は現在、優先再取得手続き中のため選択できません」と案内する。
- 管理者とイベント編集許可者は、優先再取得中でもイベント進行調整のため代理割り当てできる。代理確保時は本人通知を必須にする。
- 枠取り直し時は元枠と同じ日付・時間帯の周辺を優先表示し、時間なしスロットでは内部ソート順・番号連番で連続判定する。
- 最大連続取得数を変更しても既存予約には影響させない。受付終了後の例外的な取り直しは管理者とイベント編集許可者のみ操作できる。
- 確保者名を公開するか、匿名化するか、非表示にするかをイベントごとに切り替える。
- `custom_questions`、`editable_fields`、削除権限を管理する。
- 担当イベント内作品の `primary_event_id` を確認し、必要に応じて主イベントを変更する。
- イベント協力者を追加し、`event.basic`, `event.slots`, `event.members`, `event.questions`, `videos.title`, `videos.music_credit`, `videos.members`, `videos.review_data`, `videos.youtube_id`, `videos.primary_event` を個別に付与する。協力者管理はイベント編集許可者以上に限定し、イベント協力者へは付与しない。
- 運営メンバー、協力者、スロット、カスタム質問は CSV 入力に対応し、各入力欄に CSV 作成プロンプトをコピーするボタンを置く。
- `voided` の最終操作は管理者専用にする。イベント編集許可者は担当イベント内の作品について、無効化要請フラグと理由を送れる。
- アーカイブ後も終了済み枠の名義修正は可能にする。公開反映は次回の静的JSON生成を待ち、D1への即時クエリで公開表を更新しない。

## 4. 監査
- イベント設定の変更は変更前後を `history_logs` に残す。
- イベント編集許可者は担当イベントの監査ログのみ確認できる。担当外ユーザーのDiscord連携詳細や他イベント予約詳細はマスクする。
- 部分失敗時は「枠解放のみ再試行」「ステータス強制整合」の個別復旧ボタンを出す。
