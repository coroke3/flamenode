## Accepted design (D-19-2)

Use a fresh, request-local joined admission snapshot after Origin validation and session resolution. The successful path joins the authenticated user's ToS/actor/active-X projection to the unique `system_settings.id='default'` row. This lets CostGuard and audit retention settings use the same exact settings row and lets the audit actor snapshot use the same user row. No global or cross-request authorization cache is introduced.

A missing settings row is represented as a null settings projection, not a missing user: identity remains valid and CostGuard returns the existing `maintenance_mode` denial.

Failure provenance is preserved:
1. If the joined read fails, retry the canonical ToS/identity read first.
2. If that ToS read fails, preserve `503 db_unavailable`.
3. Only after identity passes, retry the canonical CostGuard settings read.
4. If that read fails, preserve `503 cost_guard_blocked`.
5. If the fallback succeeds, evaluate the same CostGuard core and audit settings as the successful joined path.

The fallback is failure-only; successful requests use one admission read. Identity denial still precedes CostGuard fallback and active-X denial. Active-X validation, session expiry, Origin precedence, actor attribution, audit/CAS/Queue atomicity, and 50-query ceilings remain unchanged.
