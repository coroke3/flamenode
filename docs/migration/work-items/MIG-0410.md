## Owner steps (production; each needs explicit approval — none were run)

The production deploy script applies only `CREATE INDEX IF NOT EXISTS` migrations automatically
(`scripts/safe-d1-auto-migrate.mjs`) and **fails the deploy** on any other pending migration, so
0065 must be applied by hand before the first production deploy that contains it:

1. `npm run db:remote-apply` (applies pending `migrations/` to `flamenode_db`; check the list first with `npx wrangler d1 migrations list flamenode_db --remote`).
2. Workers Builds project of the public site (MIG-0509) → Settings → Build → Deploy Hooks → create a hook for the production branch; copy the URL.
3. `npx wrangler secret put PUBLIC_BUILD_DEPLOY_HOOK_URL --config workers/fast-jobs/wrangler.toml` (paste the URL; never commit or log it).
4. Deploy `flamenode-fast-jobs` through the usual production path. Without step 3 the stage is a no-op (T07).
