# イベント管理・スロット管理ページ設計 (`/admin/events`)

## 1. 概要
イベントの作成、開催期間の設定、募集枠（スロット）の生成、および権限管理を行うためのツール。管理者だけでなく、特定のイベントに紐付けられた「イベント編集許可者」も操作可能な範囲を持つ。

## 2. 権限モデルとアクセス制御

### 2-1. ロール定義
- **管理者**:
  - システム全体の最高権限。全イベントの作成・編集・削除、全作品の編集権限設定、X ID 承認、イベント編集許可者の承認が可能。
- **イベント編集許可者**:
  - 特定の `event_id` に対して権限を付与されたユーザー。
  - **承認条件**: 管理者によって `event_editors` テーブルに登録された場合に有効となる。
  - 許可されたイベントに限り、イベント説明、イベント枠設定、運営メンバー設定、イベント内作品の編集権限設定、イベント内作品内容そのものを操作できる。

### 2-2. 操作可能範囲のマトリクス
| 機能項目 | 管理者 | イベント編集許可者 |
| :--- | :---: | :---: |
| イベントの新規作成・開催承認 | ○ | 承認後のみ |
| 開催スケジュールの変更 | ○ | 担当イベントのみ |
| スロット形式・生成設定 | ○ | 担当イベントのみ |
| 企画説明・メタデータ編集 | ○ | 担当イベントのみ |
| イベントアクセントカラー設定 | ○ | 担当イベントのみ |
| 動画収集情報 (カスタム質問) | ○ | 担当イベントのみ |
| イベント内作品の編集権限設定 | ○ | 担当イベントのみ |
| イベント内作品の削除権限設定 | ○ | 担当イベントのみ |
| イベント内作品内容の編集 | ○ | 担当イベントのみ |
| イベント編集許可者の追加・承認 | ○ | × |
| イベント協力者の追加・権限設定 | ○ | 担当イベントのみ |
| イベントの完全削除 | ○ | × |

## 3. デザイン方針

- **コンセプト**: "Event Architect" (祭典を設計する)
- **レイアウト**:
    - **イベント一覧**: 開催中、準備中、アーカイブをステータス別に整理した表形式。
    - **スロット・エディタ**: 
        - **一括生成ウィザード**: イベント日時を指定し、D1の複数行 `INSERT` でスロットを自動生成するツール。
        - **柔軟な刻み設定**: 5〜60分など任意の刻み、開始/終了時刻、枠数をセット単位で定義。
        - **予約表 UI**: 時間に紐付く枠はホットペッパービューティー風に、時間と空き状況（○ / ×）が1対1で対応して見える表にする。
        - **数量ベースの簡易生成**: 「開始/終了 + 枠数」で間隔を自動計算する方式も併設。
- **視覚演出**: 管理ミスを防ぐため、`--bg-surface` を背景に、セル境界は `--border-subtle` で整理。

## 4. 各機能の詳細解説

### 4-1. イベントマスタ編集・スケジュール設定
*   **編集可能項目**: タイトル、外部画像URLまたは旧データ由来画像URL、開始/終了日時、公開ステータス (`is_active`)、アーカイブ状態 (`is_archived`)、イベントグループ、代表者、運営メンバー、イベントアクセントカラー (`accent_color`)。
*   **イベント編集許可者の権限**: 割り振られたイベントに限り、スケジュールの調整、説明文の更新、イベント内作品内容の編集、イベント協力者の追加・権限設定が可能。
*   **公開表示**: 公式イベントと第三者イベントは同じ見え方にする。代表者と運営メンバーは「公開するメンバー」と「管理画面だけで見えるメンバー」に分ける。
*   **イベントアクセントカラー**: HEX 入力を許可する。ライト/ダーク背景や白黒文字とのコントラストが不足する、背景と同化するなどの不適当な色は警告を出す。警告後も保存は可能だが、公開前確認を必須にする。

### 4-2. スロット形式・生成機能
*   **形式の切り替え**: 
    - **日時形式**: 特定の日時に基づくスロット（例：20:00〜20:05）。
    - **数値形式**: 日時を問わない連番スロット（例：No.1, No.2...）。
*   **生成ロジック**: イベント編集許可者も、担当イベントでは「時間ベース」または「数量ベース」での一括生成を実行できる。
*   **時間ありスロット UI**: 日付ごとに行または列を分け、時間と空き状況（○ / ×）が対応して見える表にする。「この時間が取れる」と直感的に分かることを優先する。
*   **連続枠取得**: 連続枠の取得に対応する。最大連続取得数はイベントごとに設定し、既定は最大3枠とする。
*   **確保者名表示**: すでに確保された枠について、誰が取ったかを表示するか非表示にするかをイベントごとに切り替えられる。
*   **時間なしスロット**: 時間に紐付かない枠は、番号、ラベル、空き状況が分かればよい簡易リストとして扱う。
*   **代理確保**: 管理者と当該イベントのイベント編集許可者は、ユーザーの代理で枠を確保できる。代理確保時も `discord_user_id` は操作した管理者/イベント編集許可者、`x_user_id` は実際のクリエイター名義として分けて保存する。
*   **X ID却下後の優先再取得**: 自動解放された元枠は24時間だけ元投稿者へ優先再取得導線を出す。新しい予約に元の `reservation_group_id` は引き継がず、旧枠と新枠の対応は `history_logs` に残す。
*   **優先再取得中の表示**: 一般ユーザーには「選択不可の空き（確保処理中）」として表示し、「この枠は現在、優先再取得手続き中のため選択できません」と説明する。管理者とイベント編集許可者は例外的な代理割り当てができる。
*   **枠取り直し補助**: 枠取り直し画面では、元枠と同じ日付・時間帯の周辺を優先表示する。元枠が他者に取られている場合、代替枠があれば出し、なければ代替なしとして扱う。
*   **連続枠の判定**: 時間ありスロットは連続した時間枠、時間なしスロットは内部ソート順・番号連番で判定する。既存予約は、後から最大連続取得数が変更されても無効化しない。
*   **受付終了後の例外**: 受付終了後の枠取り直しは、管理者と当該イベントのイベント編集許可者だけが例外的に許可できる。
*   **公開表への反映**: 名義修正や自動解放の公開反映は、D1 即時クエリではなく次回の静的JSON生成を待つ。目標は5〜10分以内とする。
*   **キャンセル待ち**: キャンセル待ち機能は持たず、空き通知と手動確認の運用に留める。

### 4-3. 動画情報収集（カスタム質問）設定
*   **役割**: エントリー時や動画投稿時にユーザーに求める追加情報（使用ソフト、ジャンル等）を定義。
*   **内部ロジック**: `custom_questions` (JSON Array) を編集し、フォームの動的生成ルールを管理する。

### 4-4. イベント編集許可者 管理機能
*   **承認フロー**:
    1. 管理者が、対象ユーザーの X ID を入力。
    2. `event_editors` テーブルにレコードが追加される。
    3. 対象ユーザーがログインすると、管理画面の「担当イベント」一覧に当該企画が表示されるようになる。
*   **公開範囲**: 各メンバーに `is_public` を持たせ、公開ページに出すメンバーと管理画面だけで見えるメンバーを分ける。
*   **役職名**: 公開ページには `public_role_label` を表示し、内部向けの詳細やメモは `internal_note` に留める。

### 4-5. 編集可能フィールド設定機能
*   **役割**: ユーザーが後から編集できる動画項目の範囲を制御。
*   **設定範囲**: `editable_fields` (JSON) と削除権限設定の更新。イベント編集許可者も担当イベントの性質に合わせて柔軟に変更可能。
*   **過去作品**: 終了イベントやインポート済み過去作品についても、イベント単位で編集権限と削除権限を設定できる。管理者は全イベント、イベント編集許可者は担当イベントに限って操作する。
*   **協力者権限との関係**: イベント単位の協力者権限は、このイベント編集可能フィールド設定の範囲内でのみ有効にする。
*   **voided要請**: `voided` の最終操作は管理者専用とし、イベント編集許可者は担当イベント内の作品に対して無効化要請フラグと理由を提出できる。

### 4-5-1. イベント協力者 管理機能
*   **役割**: イベント単位で補助編集者を追加し、権限キー単位で編集可能範囲を設定する。
*   **承認**: 協力者本人の承認は不要。管理者または当該イベントのイベント編集許可者が追加した時点で有効にする。
*   **UI**: 協力者ごとに名前、X ID、Discord ユーザー、公開スタッフとして表示するか、公開役職名、権限キー一覧を表示する。権限キーはチェックボックスで個別に切り替える。
*   **権限キー**: `event.basic`, `event.slots`, `event.members`, `event.questions`, `videos.title`, `videos.music_credit`, `videos.members`, `videos.review_data`, `videos.youtube_id`, `videos.primary_event` を標準候補とする。`collaborators.manage` はイベント協力者には付与せず、協力者管理はイベント編集許可者以上に限定する。
*   **保存**: `event_collaborator_permissions` に1権限1行で保存する。チェックを外した権限は `allowed = 0` にするか、行を削除する。
*   **公開表示**: `is_public_staff = 1` の協力者のみ、イベント詳細ページの運営メンバー欄に表示する。編集権限を持つだけの協力者は公開しない。
*   **CSV**: 協力者は CSV で一括追記できる。既存協力者と同じ X ID があっても自動更新せず、重複警告を表示する。

### 4-6. primary_event_id 管理
*   **役割**: 作品が複数イベントに属する場合、どのイベントのアクセントカラーと文脈を優先するかを決める。
*   **UI**: イベント内作品一覧に「主イベント」選択を置き、対象作品の `videos.primary_event_id` を更新できる。
*   **権限**: 管理者は全作品、イベント編集許可者は担当イベントに属する作品、作品所有者は自分の作品に限って変更できる。ただしイベント編集許可者の担当外イベントを主イベントにする操作は管理者確認を必要とする。

### 4-7. イベントグループとアーカイブ
*   **イベントグループ**: シリーズ、年度、主催、企画カテゴリなどでイベントをまとめる。イベント一覧ではグループ別フィルタと折りたたみを提供する。
*   **アーカイブ**: 終了したイベントは削除せず `is_archived` で管理する。紐づく作品、スロット、運営メンバー、協力者履歴を残し、公開イベントページや旧形式エクスポートから参照できるようにする。
*   **終了済み枠の名義修正**: アーカイブ後も、管理者および担当イベントのイベント編集許可者は終了済み枠の表示名を修正できる。公開反映は次回静的JSON生成を待ち、変更履歴は `history_logs` に残す。

## 5. 詳細UIロジックとステート管理

### 5-1. スロット生成プレビュー
*   **UI**: 「開始時刻 / 終了時刻 / 何分間隔」等を入力すると、生成されるスロット数とタイムラインを即時シミュレーション表示。
*   **予約表プレビュー**: 時間ありスロットでは、生成前に日付・時間・空き状況の表を表示する。連続取得可能な範囲は横または縦にハイライトする。

### 5-2. 競合検知とバリデーション
*   **ロジック**: スケジュールが重複する場合や、スロット数が上限を超える場合に警告を表示。

### 5-3. 監査ログ (Audit Trail)
*   **記録**: イベント編集許可者によるスケジュールの変更やスロット生成は、すべて `history_logs` に `operator_discord_id` と共に記録され、管理者が後から追跡可能。
