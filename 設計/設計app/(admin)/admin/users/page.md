# ユーザー管理ページ設計 (`/admin/users`)

## 2. デザイン方針

- **コンセプト**: "User Sentinel" (コミュニティの秩序を守る)
- **認証基盤**: ログインは Discord のみ。通知は Discord Bot 経由に集約する。
- **識別軸**: フロント表示は X ID 基準、Discord はアクセス主体として管理する。
- **レイアウト**:
    - **リンクマップ**: 左に Discord ユーザー、右に X ID、中央にリンク状態を可視化する双方向ビュー。
    - **ユーザーグリッド**: Discord 軸 / X 軸の切替で、UID、表示名、連携ステータス、ロールを一元管理する。
    - **詳細ドロワー**: ユーザー選択時に右側からスライドイン。
        - **権限・ロール管理**: Admin権限等の変更。変更時には「操作目的」の入力と管理者再認証を必須化。
        - **手動アサインツール**: X ID / Discord を相互に検索し、リンクの新規作成・解除・共有を手動で制御する。
- **視覚演出**: 管理ミスを防ぐため、高権限ロールやバン状態にはアクセントバッジを付与。`--bg-surface` を背景に、重要なステータスのみをグローで強調します。
- **体験**: バン処理実行時には、関連する全動画の非表示化と、他管理者へのリアルタイム通知が連動するアトミックなワークフロー。

## 3. 目次・機能一覧

1. **Discord/X 連携マップ・検索機能**: 双方向の紐付け可視化
2. **X ID アクティブ切替機能**: `active_x_user_id` の変更
3. **リンク衝突・共有IDの管理機能**: 多対多の調整
4. **管理者権限（ロール）付与・剥奪機能**: Adminフラグの操作
5. **アカウントバン・停止機能**: 特定ユーザーのアクセス制御

## 4. 各機能の詳細解説

### 1. Discord/X 連携マップ・検索機能

*   **役割:** Discord と X ID の相互関係を双方向で把握し、紐付けの整合性を保つ。
*   **内部ロジック:** `user`, `x_users`, `x_account_link_requests`, `x_user_aliases` を結合し、Discord 軸 / X 軸の切替ビューで表示する。
    *   **Primary Link**: `x_users.linked_discord_user_id` を主リンクとして表示。
    *   **Secondary Link**: `x_account_link_requests.status = approved` を共有リンクとして表示。
    *   **検索**: Discord UID / X ID / 表示名での即時検索。

### 2. X ID アクティブ切替機能

*   **役割:** 1つの Discord アカウントが複数 X ID を持つ場合に、現在の使用 ID を明示する。
*   **内部ロジック:** `users.active_x_user_id` を更新し、フロントの編集権限と表示人格を切り替える。
    *   **UI**: アクティブ ID をバッジ表示し、切替時は管理者確認を必須。

### 3. リンク衝突・共有IDの管理機能

*   **役割:** 同一 X ID を複数 Discord が共有するケースや、1 Discord が複数 X ID を持つケースを安全に制御する。
*   **内部ロジック:**
    *   **衝突検知**: 既にリンク済みの X ID を別 Discord が申請した場合に警告を表示。
    *   **共有リンク**: 共有を許可する場合は「Primary / Secondary」を明示し、セカンダリは管理者承認済みであることを示す。
    *   **履歴記録**: 共有・解除・上書きの操作は `history_logs` に記録。

### 4. 管理者権限（ロール）付与・剥奪機能

*   **役割:** 運営メンバーが新しく加入した際などに、Admin権限を安全に渡す。
*   **内部ロジック:** `user` テーブルの `role`（`"admin"` / `"user"` 等）を切り替えるプルダウンを設ける。自分自身の権限を不注意で剥奪しないようなバリデーションを入れる。

### 5. アカウントバン・停止機能

*   **役割:** スパム行為や規約違反を行ったユーザーのプラットフォーム利用を停止させる。
*   **内部ロジック:** ユーザーの `is_banned` フラグを `true` に設定するボタンを開設。これが `true` になっているユーザーは、APIレベルのセキュリティルールやミドルウェアにより動画の投稿・イベント参加を含めた全ての書き込みアクションがブロックされる。

## 5. 詳細UIロジックとステート管理

### 5-1. リンクマップの二軸ビュー
*   **UI**: 「Discord 軸」「X 軸」「リンクマップ」の3モードを切替。
*   **挙動**: 片側を選択すると反対側の関連アカウントのみをハイライトする。

### 5-2. リンク衝突の警告と解決
*   **警告**: 同一 X ID への複数リンク申請を赤色バッジで表示。
*   **解決**: Primary 指定、共有許可、リンク解除のいずれかを選択。

### 5-3. アクティブ X ID 切替
*   **UI**: Discord ユーザーの詳細ドロワーに「Active X ID」を表示。
*   **挙動**: 切替時は確認ダイアログと管理者再認証を要求。

### 5-4. 権限変更の二段階認証

*   **セキュリティ**: 管理者権限（Admin）を他ユーザーに付与する際、誤操作を防ぐために「本当に付与しますか？」という確認ダイアログの表示と、操作実行者の再ログイン確認（Re-authentication）を要求するワークフローを定義します。

### 5-5. 管理操作ログ (Audit Logs)

*   **透明性**: 誰が、いつ、どのユーザーに対して「バン」や「権限変更」を行ったかの履歴を `history_logs` テーブルに自動記録し、管理画面の下部でタイムラインとして確認できるようにします。

### 5-6. 複数プロバイダの連携状況可視化

*   **UI**: ユーザーが Discord と X の両方を連携している場合、それぞれのアイコンを表示。未連携の場合は `x_account_link_requests` ステータスをバッジで表示し、運営が手動で承認・紐付けを補助できるボタンを配置します。
*   **承認ロジック**: 
    - ユーザーが `requested_x_id` を申請（`x_account_link_requests`）。
    - 管理者が承認ボタンを押下すると、Primary は `x_users.linked_discord_user_id` を申請者UIDで更新し、Secondary は `x_account_link_requests` の承認済みリンクとして保持する。
    - 必要に応じて `x_user_aliases` に旧IDを追加する。
    - `x_account_link_requests.status` を `approved` に更新し、`x_users.approval_status` を `approved` に更新する。
*   **却下ロジック**:
    - 管理者が X ID 申請を却下した場合、`x_account_link_requests.status` と `x_users.approval_status` を `rejected` に更新する。
    - 同時に `slots.x_user_id` が該当 X ID で、対象イベントが受付中（`events.is_entry_open = 1`）かつ `status = "reserved"` の未提出枠を検索する。
    - 該当枠は `status = "available"` に戻し、`discord_user_id`, `x_user_id`, `display_name` を NULL にして解放する。元投稿者には24時間の優先再取得導線を出すため、`priority_reclaim_video_id` と `priority_reclaim_until` を設定する。
    - `submitted` 済み枠に紐づく受付中イベントの作品は `status = "x_reapply_required"` にし、ユーザーへ枠の取り直しを先に促し、その後 X ID 再申請または既存承認済み X ID への付け替えを行うウィザードへ誘導する。
    - 再申請が作成されたら、対象作品の `x_reapply_request_id` に再申請を紐づけ、元データを保持する。期限は7日とし、3日前と24時間前にリマインドする。管理者だけ最大 +7日、合計14日まで個別延長できる。期限切れまたは受付終了まで未対応の場合は `voided` にする。
    - 終了済み企画、募集終了済み企画、`submitted` 済み枠は履歴保持のため自動解放しない。
    - 却下理由は auth 側で本人へ表示する。公開文面テンプレートは「プロフィール未確認」「ID不一致」「非公開アカウント」「その他」を用意し、管理者が本人向け文面を編集できる。内部メモは本人向け文面と完全に分離する。
    - X ID 却下、枠解放、作品状態変更、通知送信は `history_logs` に個別記録する。通知失敗時は管理画面のタスク一覧へ出す。
    - 運営は必要に応じて作品を `voided` に変更できる。`voided` は公開・一覧・旧形式エクスポート・ランキングから除外し、監査ログと管理者統計の別枠で追跡する。操作は作品IDまたは `VOID` の確認入力を求める二段階確認必須とし、本人向け通常表示は「不備」に統一する。
    - `voided` の復旧は管理者のみ可能。イベント編集許可者は復旧要請だけを出せる。180日経過後は物理削除候補にできる。
    - 再申請が承認され、枠取り直しが完了した作品は自動的に `pending` へ戻す。既存承認済み X ID へ付け替える場合は、作者表示名とアイコン候補を付け替え先 X ID に同期する。旧却下 X ID は公開ページには出さず、管理画面と担当イベントのイベント編集許可者だけに履歴表示する。却下 ID は正規 alias としては保持しない。
    - 連続3回却下された X ID 再申請は一時ロックし、管理者への問い合わせを促す。X ID 統合と再申請が同時に起きた場合は再申請を優先し、統合処理は一時停止する。
