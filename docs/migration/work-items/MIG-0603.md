## Decisions (owner)
- **D-0603-1 (OPEN): post-commit Queue wake.** CURRENT passes `staticRebuildWakeSource: "web"`, so after the batch it sends one `static_rebuild_available` message (parity test `DOCUMENTED DIFFERENCE D-0603-1` proves 1 wake on CURRENT, 0 here). `apps/api` has no Queue binding or wake host, so this PR writes the durable queue row only. Options: (a) accept the row-only behaviour until the existing doorbell / recovery cron drains it (delay = cron cadence), (b) add a Queue producer binding + wake host to `apps/api` (wrangler / binding change = owner approval). This also gates SA-087 (B-5) and every later write that enqueues.
- **D-0603-2 (info): bounded event_staff read.** CURRENT reads all matching staff rows; the endpoint reads `LIMIT 100` (S2). More than 100 matching rows for <= 4 events x <= 100 approved X ids can only deny (fail closed), never grant. Not reachable with real data (<= a handful of staff rows per user).
- **D-0603-3 (info): CURRENT quirk kept.** CURRENT `updateChapter` requires a non-empty `video_id` field but never compares it with the chapter's video; the endpoint takes no video id on update/delete.
