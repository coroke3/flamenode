# FlameNode 設計確認質問

## 解決済みの決定

### 1. イベント権限ロール

- **管理者**: すべての作品の編集権限、X ID 承認、ユーザー管理、イベント承認、イベント編集許可者の承認など、全管理操作ができる。
- **イベント編集許可者**: 管理者が承認したユーザーのみ。許可されたイベントに限り、イベントの編集、枠設定、運営メンバー設定、イベント説明、イベント内作品の編集権限設定、イベント内作品内容の編集ができる。
- 旧称や英語名は使用せず、設計上は「イベント編集許可者」に統一する。

### 2. 第三者イベントの表示

- 第三者イベントは、公開ページ上では公式イベントと同じ見え方にする。
- 「外部主催」「コミュニティ主催」などのラベルは表示しない。
- 公式イベント・第三者イベントのどちらでも、公開対象に設定された代表者と運営メンバーは確認できるようにする。

### 3. X ID 統合取消期限

- X ID 統合取消は、統合完了から **180日以内** に限り受け付ける。
- 復元に必要なスナップショットは通常の履歴ログ保持期間とは別に180日保持する。

### 4. ライトモード時の動画詳細

- ライトモードは白基調にする。
- 旧ページの黒基調そのものには必ず準拠しない。ライトモードとダークモードの両方を正式実装し、色はテーマトークンを正とする。
- プレイヤー枠と独自コントロールは、映像視認性を優先して高コントラストにする。
- 作品ごとの大きな枠や余白は最小限にし、表示数を増やす。

### 4-1. 絵文字とアイコン

- UI では絵文字を使わない。
- ナビゲーション、ボタン、状態表示、警告、SNS 導線、プレイヤー操作、管理画面の操作種別には、Font Awesome を第一候補として、Lucide、Material Symbols、Iconify などの正規 SVG アイコンライブラリを使う。
- X、YouTube、Discord などのブランド導線は、ライセンス確認済みのブランドアイコンまたは公式ガイドラインに沿った SVG を使う。

### 5. 黄色アクセントとイベント別アクセント

- FlameNode の基本アクセントは、鮮やかなイベント感のある黄色にする。
- イベントごとにイベントアクセントカラーを設定可能にする。
- イベント詳細、イベント参加導線、イベント所属作品、イベント内プレイリストでは、設定されたイベントアクセントカラーを優先する。

### 6. イベントアクセントカラー入力

- イベントアクセントカラーは HEX 入力を許可する。
- 背景と同化する、ライト/ダーク背景で読みにくい、警告色と混同するなどの不適当な色は保存前に警告する。

### 7. 代表者と運営メンバーの公開範囲

- 代表者と運営メンバーは、「公開するメンバー」と「管理画面だけで見えるメンバー」に分ける。
- 公開ページには公開対象メンバーのみ表示し、内部メモや非公開メンバーは出さない。

### 8. イベント編集許可者の作品編集範囲

- イベント編集許可者は、担当イベントに紐づく作品内容そのものも編集できる。
- 変更は `history_logs` に記録し、担当外イベントの作品には触れない。

### 9. イベント別アクセントカラーの優先順位

- 複数イベント所属作品では、`primary_event_id` のイベントアクセントカラーを優先する。
- `primary_event_id` は編集可能にする。

### 10. X ID 統合取消後の履歴表示

- X ID 統合・取消の履歴はユーザー本人や公開ページには見せない。
- 内部監査ログとしてのみ保持する。

### 11. トップページの自動横スクロール

- トップページの横スクロールスライダーは自動でゆっくり流す。
- PC では矢印を表示し、手動介入できるようにする。
- ユーザーがホバー、フォーカス、ドラッグ、矢印操作をした場合は自動スクロールを一時停止する。

### 12. 動画詳細のモバイル固定プレイヤー

- 縦長スマートフォンでは、プレイヤーを上部固定にする。
- 比率は 16:9 を維持する。

### 13. 関連動画の表示件数

- 動画詳細の関連動画は標準15件、最大30件にする。

### 14. 協力者ロール

- 協力者はイベント単位の補助編集権限として扱う。
- 協力者ごと、かつ編集権限キーごとに編集可能項目を変更できる。
- 協力者追加時の本人承認は不要。管理者または当該イベントのイベント編集許可者が追加した時点で有効にする。
- 合作メンバーとして掲載されることと、協力者として編集権限を持つことは別扱いにする。

### 15. 旧データ互換と CSV

- `eventinfo.json` を基に過去イベント情報をインポートできるようにする。
- 各種入力欄では CSV インポートを可能にし、CSV 作成プロンプトをコピーするボタンを置く。
- メンバー入力時は、旧データ由来の名前・ID対応表を基に、名前からID、IDから名前を提案する。
- 旧データ形式でのエクスポートも可能にする。
- CSV インポートは追記のみを基本とし、自動更新は行わない。
- 通常エクスポートは公開データのみ、管理者向け詳細エクスポートは限定公開・非公開データも含められる。
- `eventinfo.json` の文字化け疑いは、文字コードミスの可能性を提示し、疑い行をハイライトする。修復候補は補助表示に留め、自動反映はせず、管理者が手動修正してから保存する。

### 16. イベント協力者の追加決定

- イベント協力者は、対象イベントが `video_events` で紐づいていれば編集可能にする。`primary_event_id` が別イベントでも、所属イベントに含まれていればよい。
- `collaborators.manage` はイベント協力者には付与しない。協力者の追加・削除・権限変更はイベント編集許可者以上に限定する。
- 文字化け修復候補が明らかに正しそうな場合でも自動反映はしない。原文と候補を確認用に残し、管理者が手動で採用・修正する。
- CSV 追記時の重複行は、「取り込まない」と「警告しつつ追記」をユーザーが選択できるようにする。

### 17. Cloudflare 無料枠・コストガード

- Cloudflare 無料枠内に収まる運用を優先する。
- 課金されそうな水位に近づいた場合、`economy`, `read_only`, `static_only`, `maintenance` の順に機能を自動停止する。
- 管理者は `/admin` で自動停止、手動停止、解除、しきい値変更、一時許可を操作できる。
- 詳細は `FlameNode-Cloudflare-Free-Tier-Guardrails.md` を正とする。

### 18. コストガード通知・一時許可・静的JSON

- コストガードが `economy`, `read_only`, `static_only`, `maintenance` に入った場合、管理者へ Discord DM で通知する。
- 管理画面内通知も併用し、Discord DM が失敗しても状態を確認できるようにする。
- `read_only` 中の管理者一時許可は、既定30分で自動終了する。必要な場合は30分単位で延長できる。
- 静的 JSON は通常1時間ごとに生成し、イベント開催中・受付中・公開直後は対象イベントだけ5〜10分ごとに生成する。

### 19. 画像運用とサムネイル

- Cloudflare にアップロードする画像はアイコン画像のみとする。
- アイコン画像の元ファイル上限は1ファイル8MBにする。
- 作品サムネイルは Cloudflare/R2 に保存せず、YouTube サムネイルを利用する。

### 20. 汎用分類ラベルと使用編集ソフト欄

- 作品検索・作品一覧・投稿フォームでは、汎用分類ラベル機能を採用しない。
- 使用編集ソフト欄は必要なので、チップ型入力として残す。
- 使用編集ソフトは辞書と別名候補により表記ゆれを吸収する。

### 21. 動画詳細コメント

- コメントは YouTube 風ではなく、ニコニコ動画寄りの時間軸反応として扱う。
- ただし標準 UI は一覧中心にし、コメント欄感を強く出しすぎない。
- チャプターはユーザーが自分で設定でき、公開/非公開を切り替えられる。

### 22. 独自プレイヤーのチャプター点表示

- チャプター点は `video_chapters` を正規テーブルとして扱う。
- `marker_kind = 'chapter'` または `show_on_player_bar = 1` のチャプターを再生バー上に点表示する。
- 点のホバー、タップ長押し、キーボードフォーカスでは、時刻、ラベル、種別を表示する。
- フレーム画像プレビューは必須にしない。YouTube 側から低コストに取得できる場合のみ任意対応とし、できない場合はテキストプレビューで代替する。
- Cloudflare/R2 にチャプタープレビュー画像を保存しない。

### 23. SQL整合とチャプター思想

- 初期SQLの `video_chapters` を正規名にし、時間付きコメント用の独立した `video_timestamps` テーブルは作らない。
- `video_comments` には `chapter_id` を追加し、コメントは `video_comments.chapter_id -> video_chapters.id` で対象秒数へ紐づける。
- 初期SQLの `event_managers` は旧名として扱い、正規名は `event_editors` に統一する。
- 初期SQLに不足している `is_archived` や追加テーブル群は、後続マイグレーションで補完する。

### 24. YouTube同期と閲覧数計測

- YouTube URL / ID 入力時に即時同期を試行し、投稿直後の不安を減らす。
- ユーザー本人は自分の作品に限り、1作品1日1回まで手動同期要求できる。
- 閲覧数は D1 を再生ごとに直接更新せず、Durable Object で動画ID・時間帯単位にプールし、1時間ごとに D1 へバルク反映する。

### 25. スロット主体とX ID却下時の解放

- `slots.discord_user_id` は操作したDiscordアカウント、`slots.x_user_id` は枠を確保したクリエイター名義として分離する。
- 承認待ち X ID でも枠確保を許可する。
- X ID が却下された場合、その X ID が確保している「受付中かつ未提出」の枠だけを自動で `available` に戻し、名義情報をクリアする。
- 終了した企画、募集終了した企画、提出済み作品に紐づく枠は履歴保持を優先して自動解放しない。
- 公開イベントページでは、承認待ち X ID の枠も名義のみ表示し、承認待ちバッジは出さない。
- 複数枠取得は連続する枠に限り、作品の `scheduled_time` は最初の枠を正とする。

### 26. 追加回答による確定事項

- 閲覧数の短期集約は Durable Object を正とする。KV 時間帯バケットは主経路にしない。
- `event_managers` から `event_editors` への移行は完全リネーム方針にする。互換ビューや別名テーブルは残さない。
- X ID 却下時の自動解放は、受付中で未提出の枠に限定する。終了企画と募集終了企画は保持する。
- 承認待ち X ID の公開枠表示では、承認待ち表示を出さない。
- YouTube 手動同期は、1作品につき1日1回までとする。クォータ不足時はキュー投入のみで、即時同期しない。
- 受付中イベントで提出済み作品の X ID が却下された場合、作品は削除せず `x_reapply_required` として保持し、X ID 再申請と枠の取り直しを促す。
- 再申請が作成されたら、その再申請 ID を作品の `x_reapply_request_id` に紐づけ、作品データを保持する。
- 運営は必要に応じて作品を `voided` にできる。`voided` は公開・一覧・旧形式エクスポート・スコア計算から除外し、監査ログで追跡する。
- YouTube 手動同期の上限は日本時間 0:00 にリセットする。
- Durable Object の未反映閲覧カウントは24時間保持する。

### 27. X ID再申請・枠取り直し・動画同期・閲覧数の確定事項

- X ID 再申請中の作品は、再申請中のID文字列ではなく名義を主表示にする。
- `x_reapply_required` は通常の `pending` と同じ審査一覧に出し、専用タブには分けない。
- X ID 再申請期限は7日。期限切れ、または受付終了までに枠取り直しが終わらない場合は `voided` にする。
- `voided` は物理削除ではなく、公開・上映・一覧・旧形式エクスポート・スコア計算から除外する論理無効化である。本人向けには「不備」と表示する。
- 旧却下 X ID は公開せず、管理画面だけに履歴として出す。
- `x_reapply_required` 中でも、作品本文、YouTube URL、合作メンバー、クレジットは編集可能にする。
- X ID 却下理由は auth 側で本人に表示し、管理者は公開文面を編集できる。
- X ID 再申請通知は Discord DM と管理画面通知を使い、メールは基本使わない。
- 既存承認済み X ID への作品付け替えと、新規再申請の両方を選べるようにする。
- X ID 却下後の元枠は24時間だけ優先再取得候補にする。元枠が取れない場合、代替枠がなければ「なし」とする。
- 再申請中作品は残枠数カウントに含める。
- 連続枠取り直しでは短縮・延長を許可する。時間なしスロットも同じ再取得フローにする。
- 募集終了直前でも特別猶予は設けない。
- 管理者とイベント編集許可者は代理枠確保ができる。
- 新しい予約へ元の `reservation_group_id` は引き継がない。ただし旧枠との関連履歴は管理者だけ確認できるよう `history_logs` に残す。
- 自動解放された枠は公開イベントページへ10分以内に空きとして反映する。「空きが出ました」の強調表示は出さない。
- 承認待ち X ID の公開枠表示は名義のみ。管理者ログイン時だけ承認待ち状態を補助表示してよい。
- `x_reapply_required` 作品はイベント作品一覧に「調整中」として薄く表示する。
- 本人ダッシュボードでは枠取り直しを先に誘導し、X ID 再申請と1つのウィザードにする。
- 作品詳細ページは、`x_reapply_required` について一般閲覧者、本人、管理者/イベント編集許可者で表示を分ける。
- 警告や再申請導線はタイトルと概要の下に固定表示する。モバイルでも同じ順序を保つ。
- X ID 却下処理はトランザクション相当で扱い、枠解放、作品状態変更、通知送信を `history_logs` に個別記録する。
- `voided` 操作は二段階確認必須。イベント編集許可者は担当イベント内の `x_reapply_required` 作品を確認できるが、最終無効化は管理者判断を基本にする。
- X ID 再申請承認後、作品は自動で `pending` に戻す。X ID 再申請と X ID 統合が同時に起きた場合は再申請を優先する。
- 通知失敗時は管理画面のタスク一覧に出す。`voided` 件数は管理者統計に別枠で表示する。
- YouTube 手動同期の1日1回制限は日本時間0:00リセットで固定する。管理者とイベント編集許可者は通常ユーザーの制限対象外にする。
- YouTube API クォータ不足時のキューは翌日0:00以降に自動再実行する。
- 非公開動画は公開設定確認を促す。削除済みは `youtube_sync_status = "failed"` のままユーザー修正待ちにする。
- Shorts URL、プレミア公開待ち、年齢制限付き、埋め込み不可動画はいずれも登録自体をブロックしない。
- Durable Object の未反映閲覧数は24時間保持し、反映不能時は管理者通知と監査ログに留める。
- 閲覧数の1セッションは6時間。連続再生中の各動画、自分の作品、管理者/イベント編集許可者の確認再生もカウントする。
- `economy` 中の閲覧数サンプリング率は既定50%。`read_only` 中に止めた閲覧数イベントは補完しない。
- `video_score` には YouTube 側再生数も正規化して含める。急上昇作品は24時間窓で集計する。ログイン状態は重複判定に使わない。

### 28. voided・X ID再申請・スロット・YouTube・コストガードの追加確定事項

#### A. voided・作品復旧・状態管理

- `voided` 作品は本人の通常ダッシュボード一覧から除外し、通知からのみ確認できる。
- `voided` は復旧可能だが、復旧操作は管理者専用にする。イベント編集許可者は復旧要請のみ行える。
- `voided` 作品は180日経過後に物理削除候補にできる。
- 理由カテゴリは「X ID不備」「重複投稿」「投稿者都合」「運営判断」「期限切れ」とする。
- 本人向け通常表示は「不備」に統一し、詳細文は通知内だけで伝える。
- `voided` 作品の YouTube ID は重複判定から外す。
- コメント、チャプター、いいね、ブックマークは完全削除せず、カスケード無効化で非表示保持する。
- 再登録時に旧コメントやチャプターは引き継がず、別作品として新規登録する。
- 本人からの取り下げ申請は可能とし、申請時は `voided`（投稿者都合）へ遷移する。
- `voided` 操作は作品IDまたは `VOID` などの確認文字列入力方式で二段階確認する。
- 管理者統計はイベント別・理由カテゴリ別で集計し、操作担当者別は監査ログの検索に留める。
- 管理画面検索では既定で非表示にし、ステータス `voided` フィルタを指定した場合だけ表示する。
- X ID再申請期限は7日。3日前と24時間前にリマインドし、最終確認通知は送らない。
- 連続3回却下された場合は一時ロックし、管理者への問い合わせを促す。

#### B. X ID・本人確認・名義管理

- X ID所有確認は既存手順（プロフィールへの認証テキスト記載など）を使う。
- 却下理由テンプレートは「プロフィール未確認」「ID不一致」「非公開アカウント」「その他」の4種類。
- 内部メモと本人向け文面は完全に分離し、内部メモを公開APIに乗せない。
- 既存承認済み X ID へ付け替える場合、作者表示名は付け替え先 X ID の現在表示名へ自動同期する。
- 付け替え先 X ID のアイコンは作品アイコン候補へ自動追加する。
- 再申請ウィザード開始時点の再申請対象 ID を優先・固定する。
- 再申請中は X ID 統合処理を一時停止し、主体復帰を優先する。
- X ID 一覧の表示順は「承認済み」→「再申請中」→「承認待ち」。
- 却下 ID は正規 alias として保持しない。
- 承認待ち X ID の警告は枠取得の初回のみ表示する。
- 管理者の代理 X ID 作成を許可する。
- Discord連携解除時、未公開作品は `voided`、公開済み作品は所有者不明アーカイブ扱いにする。
- 公開ページでは最新表示名のみ反映し、表示名変更履歴は管理画面の監査用に留める。
- 管理者は再申請期限を最大 +7日、合計14日まで個別延長できる。

#### C. スロット・受付・イベント運用

- 優先再取得中の元枠は、一般ユーザーには「選択不可の空き（確保処理中）」として表示する。
- 文言は「この枠は現在、優先再取得手続き中のため選択できません」とする。
- 管理者とイベント編集許可者は優先再取得中でも代理割り当てできる。
- 枠取り直しでは元枠と同じ日付・時間帯の周辺を優先表示する。
- 連続枠は他者枠と隣接していても問題なしとする。
- 時間なしスロットの連続判定は内部ソート順・番号連番で行う。
- 調整中枠は薄いグレーまたは斜線パターンで表示する。
- 名義修正は次回静的JSON生成を待って反映し、D1即時クエリを避ける。
- 代理確保時の本人通知は必須。
- 受付終了後の例外的な枠取り直しは、管理者とイベント編集許可者のみ許可する。
- 最大連続取得数の変更は既存予約に影響させない。
- キャンセル待ち機能は不要。空き通知のみの運用にする。
- 追加枠解放はイベント編集許可者が操作可能。
- 過去日付の枠表は既定で折りたたみ表示にする。
- 取得者名には X ID へのリンクを付与する。

#### D. YouTube同期・プレイヤー・動画状態

- YouTube APIの1日上限クォータを90%消費したら OGP 解析へフォールバックする。
- 埋め込み不可時はサムネイルと「YouTubeで視聴する」外部リンクを中央に表示する。
- 年齢制限付き動画も、プレイヤー中央とタイトル直下に外部リンク導線を置く。
- プレミア公開待ちのカウントダウンは OGP/API から時刻が取れる場合だけ表示する。
- タイトル・サムネイルの自動同期は確認・提案用に留め、ユーザー入力を自動上書きしない。
- YouTube側再生数は6時間ごとのバッチで同期する。
- 取得失敗時は前回値を維持し、補正係数は掛けない。
- YouTube API クォータ上限は管理画面のシステム設定で手入力可能にする。
- 手動同期履歴は、ユーザー本人には直近1回の成功/失敗日時だけ見せる。
- 動画ID変更時も既存チャプター時刻は維持する。
- 範囲外チャプターは「無効（範囲外）」としてグレーアウトし、再生バーの点表示から除外する。
- 非公開チャプターの点は本人と管理者のみ半透明で表示する。
- 2秒以内に密集する点は1点にまとめ、ホバー時に複数候補リストを出す。
- プレビューのアイコンは `marker_kind = 'chapter'` の作成者アイコンを優先する。
- モバイルでもコマ送り操作を必須にする。

#### E. 閲覧数・推薦・ランキング

- YouTube再生数は `log10(youtube_view_count + 1)` で正規化し、アプリ内閲覧数より低い係数で扱う。
- いいね数の重みは10倍固定。
- 急上昇は公開ページ（トップや一覧タブ）へ明示的に出す。
- 自身の再生、管理者、イベント編集許可者の確認再生は除外しない。
- bot抑制は IP/UA の短期ハッシュによるレートリミットを使う。
- サンプリング時の表示は補正値として扱う。
- 閲覧数停止中はサイト全体またはプレイヤー上部に簡易アラートを出す。
- 集約失敗通知は代表管理者のみに送る。
- Durable Object の集約単位は動画ID単位を主軸にし、内部で日付別バケットを持つ。
- 再生リスト由来の閲覧はスコア計算上0.5倍にする。
- 関連動画ロジック比率は `video_score` 40%、文脈近さ60%を目安にする。
- クリエイタースコアにも対数化したYouTube再生数を含める。
- `voided` はランキングから完全除外する。
- 復旧時の過去スコアは再計算対象へ戻す。

#### F. Cloudflare無料枠・コストガード

- 最初に止める動的機能は検索のフルスキャン系、次に動的推薦。
- Durable Object 危険水位では即停止せず10%サンプリングへ下げる。
- R2 Class B が増えた場合、静的JSONは Pages Static Assets へ寄せる。
- R2アイコン配信は `Cache-Control: public, max-age=86400, stale-while-revalidate=604800` を付ける。
- KV書き込み超過時はD1へ退避せず、即時ログ等をオンメモリまたは破棄へ切り替える。
- キュー優先度は Discord通知キューを優先し、YouTube同期は一時停止する。
- 使用量取得失敗時は保守的に `economy` へ遷移する。
- `static_only` 中もログインページとセッション検証は最小限残す。
- `maintenance` 中は事前生成済み静的HTML/JSONだけ閲覧可能にする。
- 解除の二人確認は不要。管理者単独操作で復旧できる。
- 機能制限中バナーは全画面上部に目立つように出す。
- イベント中でも無料枠超過は許容せず、事前に手動ガードをかける。
- D1読み書き、または Pages Functions 要求が無料枠80%超えを2か月継続したら有料化・構成見直しを検討する。
- 古いアイコンは月次ワーカーで最大200KB程度のWebPへ圧縮し、上書き置換する。
- 静的JSONは直近3世代のみ保持する。

#### G. 管理画面・監査・権限

- 通常ログは90日、X ID関連と `voided` 関連ログは180日保持する。
- 監査ログ閲覧は管理者と担当イベント内のイベント編集許可者まで。
- 協力者編集の履歴は本人ダッシュボードでも作品編集履歴として見せる。
- `voided` 操作は管理者専用。イベント編集許可者は申請フラグだけ立てられる。
- 旧却下IDはイベント編集許可者にも確認用として見せる。
- タスク一覧優先度は「コストガード」→「X ID再申請」→「YouTube同期失敗」。
- DM通知の再送は最大3回、指数バックオフ。
- 危険操作と一時許可延長は理由入力必須。
- 担当外ユーザーのメールアドレス、Discord連携詳細、他イベント予約詳細はマスクする。
- 協力者権限のCSV導入は、イベント編集許可者にも担当イベント内に限り許可する。
- 代理編集は公開ページに表示せず、本人編集画面と監査ログにだけ残す。
- 部分失敗時は「枠解放のみ再試行」「ステータス強制整合」の個別ボタンを出す。
- 旧名参照のCIチェックを導入する。

#### H. CSV・旧データ・アーカイブ

- `x_reapply_required` は管理者・運営向け詳細レポートには状態フラグ付きで出す。
- `voided` は監査・統計専用の別レポートにのみ出す。
- 列名ゆれは一般的な辞書エイリアスと正規表現で自動判定する。
- 文字化け修正は必須にせず、一括スキップを許可する。
- 外部画像URLは Cloudflare へ保存せず参照のみで維持する。
- 運営メンバー公開範囲が不明な場合は非公開（管理画面のみ）を既定にする。
- 時間なしスロットとして連番取り込みできる。
- 旧データX IDは未承認X ID（プレースホルダー）として作成する。
- 旧出力の文字コードは UTF-8 固定。
- アーカイブの名義修正履歴は公開ページには表示しない。

#### I. 公開UI・デザイン・アクセシビリティ

- 調整中表示は opacity 0.5 程度にし、テキストで「調整中」バッジを重ねる。
- 警告帯は警告色の視認性を優先し、イベントアクセントカラーは枠線などに留める。
- 左カラム警告導線は sticky にする。
- モバイル固定プレイヤー下にコンパクトな固定CTA帯を置く。
- ニコニコ風流しコメントは将来の任意機能、既定OFF。
- チャプターとコメントはタブ分けする。
- 関連動画は「同じ作者」「同じイベント」「おすすめ」などでセクション分けする。
- 再生リストUIは関連動画より上の右レール最上部に置く。
- スマホのスプレッドシート表は横スクロールを維持し、日付ごとのカード列にも切り替えられるようにする。
- `prefers-reduced-motion` 有効時は自動横スクロールを完全停止する。
