## Decision (Fable, owner-delegated, 2026-10-23)

- **ZERO_1102 §3 予算 B**: 名目 10ms / 設計 8ms を維持する。次の2つに分ける。
  - **B-new**（新規の単位: MIG-0411 のページ描画、MIG-0610 の分割 job、MIG-0509 の shard）: 非本番の実プラットフォームで warm の最大値 < 8ms。cold は記録するが合否に使わない。
  - **B-add**（既存の Cron / Queue Worker に段を足す変更）: 段の増分（after − before、同じ条件・同じ n）の最大値 ≤ 2ms、かつ Worker 全体の warm 最大値が本番の既存 baseline を増分より多く超えない。Worker 全体を 8ms に収めるのは MIG-0609（測定）/ MIG-0610（分割）の仕事。
- **ZERO_1102 §5 測定の注記**: `wrangler tail` の cpuTime は整数 ms（±1ms）。wrapper の overhead は増分では打ち消される。cold の値は別に記す。打ち切られた時点の cpuTime は途中の値で、上限の推定に使わない。公式の方法は「非本番 Worker + tail cpuTime」（workerd profiler に代わる）。
- **ZERO_1102 §1 Queue consumer の上限**: 名目 10ms + 文書にない猶予。100ms は通り、1s は断続的に打ち切られる。本番の「50ms 超過」の記録は打ち切り時点の途中の値。8ms（B-new）を維持し、猶予に頼らないので shard の上限は引き上げない。U07 の件数: 20ms 0/49、100ms 0/39、1000ms 23/43（下限値。tail の取りこぼし 19件）。
