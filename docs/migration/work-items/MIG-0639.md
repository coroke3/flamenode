## 2026-11-10 SEC-575 RH-013 warm-cache measurement extension

- Added separate `scheduled-warm` and `realtime-warm` measurement kinds to the existing RH-013 scenario; the existing normal/limit scheduled path with explicit cache clearing remains the full-rebuild control.
- Each warm sample is primed by an unmeasured request on the same local workerd target, then the immediately following request is profiled. ### 2026-11-10 warm-cache proof hardening

- Added SHA-256 response-body fingerprints outside the workerd profiler window. Scheduled warm samples require both `X-FlameNode-Cache: HIT` and byte-identical body to the prime response.
- Realtime micro-cache responses use the same `BYPASS` header for hit and miss, so the harness now waits 1.1 seconds after priming (crossing `generated_at_unix` while remaining inside the 15-second isolate-cache TTL) and requires the measured response body to be byte-identical to the primed body. A cache miss rebuilds with a changed timestamp and is counted as unexpected.
- This distinguishes actual realtime body reuse from a cold rebuild without modifying application handlers or adding production headers. The extra wait is outside the profiled request; only the measured request contributes CPU.
