# イベント詳細ページ設計 (`/event/[id]`)

## 1. 概要
特定のイベントの詳細情報（テーマや概要、運営陣の情報）と、そのイベントに紐づいて投稿された作品、確保済み枠、アーカイブ情報を表示・振り返るページです。終了したイベントも削除せず、アーカイブとして残す。

## 2. デザイン方針

- **コンセプト**: "Event Landmark" (祭典の記憶が息づく場所)
- **レイアウト**:
    - **メインエリア**: 
        - イベントバナーまたは外部画像URL由来のキービジュアル。
        - イベント情報（タイトル、開催期間、詳細な説明文）。
        - イベント代表者と、公開対象に設定された運営メンバーリスト（Role, Name, SNSリンクの構成）。
    - **作品グリッドエリア**: そのイベントに属する全ての作品をカード形式で一覧表示（上映順ソートを推奨）。
- **視覚演出**: バナーエリアには `FlameNode-Design-System.md` の黄色アクセントを基本に、イベント別アクセントカラーが設定されている場合はその色を適用します。公式イベントと第三者イベントは同じ見え方にし、代表者と運営メンバー情報で運営主体を確認できるようにします。
- **体験**: 「全作品を連続再生」ボタンを設置し、アーカイブとしての利便性を向上させます。イベント内の動画リストを動画詳細ページへ渡し、再生リストとして扱えるようにします。


## 3. 目次・機能一覧
1. **イベントメタデータ表示機能**: イベント概要文、バナー画像等の描画
2. **代表者・運営メンバー表示機能**: イベントに関わったメンバーのリスト化
3. **スロット公開機能**: 現在確保されている枠の一覧表示
4. **イベント所属作品の取得・グリッド表示機能**: 出展作品の網羅的表示
5. **ステータスバッジ動的表示機能**: 非公開等のバッジ出し分け
6. **連続再生・プレイリスト生成機能**: イベント内の動画を連続再生
7. **エラー・存在しないイベントのハンドリング機能**: NotFound対応

## 4. 各機能の詳細解説

### 1. イベントメタデータ表示機能
*   **役割:** このイベントがどのようなテーマ・内容だったかを示す。
*   **内部ロジック:** パラメータの `[id]` と一致するレコードを `events` テーブルから取得し、`explanation` (概要テキスト) や `title`, `icon_url`, `img_url` (ヘッダー画像URL)の情報を上部にレンダリングする。
  - **既存再現**: `event.img` が存在する場合は、ヒーローセクションのメインバナーとして表示する。

### 2. 代表者・運営メンバー表示機能
*   **役割:** そのイベントの代表者と運営メンバー情報をクレジットとして表示する。
*   **内部ロジック:** `events.representative_x_user_id`、`event_editors`、`x_users` を `join` して代表者・運営メンバー情報を取得し、名前・役割・SNSへのリンクURLという箇条書きリストを生成する。
  - **既存再現**: スタッフ名、担当（Post）、およびTwitter ID（リンク付きXアイコン）を表示する。
  - **公開範囲**: `event_editors.is_public = 1` のメンバーのみ公開ページに表示する。管理画面だけで見えるメンバーや内部メモは公開ページへ出さない。

### 3. スプレッドシート風スロット公開機能

- **役割:** イベント開催前や期間中、どの枠（時間帯）に誰がエントリーしているかをオープンにする。
- **内部ロジック:** 
  - `slots` テーブルから `event_id` に紐づく全スロットを取得。
  - 各スロットの `display_name`（確保時に必須入力）、`x_user_id`、ステータスを時系列順にリスト化。
  - **公開ルール**: イベント設定の `slot_visibility_mode` に従って、確保者名を表示、匿名化、非表示に切り替える。
  - **表示形式**: スプレッドシート風の表で表示する。
    - 日付
    - 時間
    - 誰が取得したか
    - ステータス（available / reserved / submitted）
  - **承認待ち X ID**: 承認待ち名義でも枠一覧には `display_name` だけを表示する。承認待ちバッジや審査状態は公開ページには出さない。
  - **管理者表示**: 管理者ログイン時だけ、承認待ち X ID の枠に管理用の承認待ち状態を補助表示してよい。一般公開では表示しない。
  - **X ID 却下時**: 受付中イベントで X ID が却下されて自動解放された未提出枠は10分以内に空きとして反映し、公開履歴には却下理由を出さない。「空きが出ました」のような強調表示は出さない。提出済み作品は公開側では `調整中` として薄く表示し、ユーザーの再申請と枠取り直しが完了するまで通常作品一覧・上映順には戻さない。終了済み・募集終了済みの企画枠は履歴保持のためそのまま表示ルールに従う。
  - **優先再取得中の枠**: 一般ユーザーには薄いグレーまたは斜線パターンの「選択不可の空き（確保処理中）」として見せる。文言は「この枠は現在、優先再取得手続き中のため選択できません」とする。
  - **終了済み枠の名義修正**: アーカイブ後でも、管理者および担当イベントのイベント編集許可者は履歴保持された終了済み枠の名義を後から修正できる。修正は `history_logs` に残し、公開反映は次回の静的JSON生成を待つ。
  - **リンク**: 取得者名には X ID へのリンクを付与する。
  - 同じ日付が連続する場合は、日付セルをまとめる、または日付見出しで区切って見やすくする。
  - 過去日付の枠表は既定で折りたたみ表示にする。
  - スマホでは横スクロール表を維持しつつ、切り替えボタンで日付ごとのカード列表示に崩せるようにする。
  - 時間に紐付かないスロットは、番号またはラベルと空き状況だけを簡易表示する。

### 4. イベント所属作品の取得・グリッド表示機能

- **役割:** 当該イベントの目玉となる、投稿されたすべての動画を一覧表示する。
- **内部ロジック:** `videos` と `video_events` (中間テーブル) を `join` して、当該イベントに所属する全データを取得。`scheduled_time` などを指標に「上映された順番」または「新着順」等でソートして、動画用カードコンポーネントをグリッドで敷き詰める。
- **`x_reapply_required` 表示**: 受付中イベントの提出済み作品で X ID 再申請が必要なものは、完全非表示ではなく「調整中」として opacity 0.5 程度で薄く表示し、テキストバッジを重ねる。ただし通常の上映順、再生リスト、旧形式エクスポートには戻さず、本人の再申請と枠取り直し完了後に通常ステータスへ復帰する。
- **`voided` 表示**: `voided` 作品は公開イベントページ、作品一覧、再生リストから除外する。管理者や担当イベント編集許可者だけが管理導線から確認できる。

### 4. ステータスバッジ動的表示機能
*   **役割:** サムネイルを見ているユーザーに対し、その動画が現在どの公開ステータスにあるかを補助的に示す。
*   **内部ロジック:** 取得した `videos` の `status` が `"unlisted"` なら鍵マークと「限定公開」の文字を、`"private"` や承認待ちなら「非公開」のレイヤーと文字をカード下部などに重畳表示する。`x_reapply_required` は「調整中」として控えめに表示し、`voided` は表示対象外にする。

### 5. エラー・存在しないイベントのハンドリング機能
*   **役割:** 間違ったURL等でアクセスされた際のエラー体験を向上させる。
*   **内部ロジック:** fetch実行時にデータが存在しない、または無効なデータが返還された場合は `notFound: true` 扱いにし、Next.js の 404画面、もしくは専用の「エラーが発生しました」という UI画面を表示してトップへ誘導する。

## 5. 詳細UIロジックとステート管理

### 4-1. 時系列自動並び替え (Chronological View)
*   **初期状態**: 「上映スケジュール順」で表示。
*   **内部ロジック**: `videos.scheduled_time` をキーにして昇順でソート。同日の枠（昼・夜）がある場合は `scheduled_time` の秒単位まで正確に比較し、実際のイベント進行に即した順序で作品を並べます。

### 4-2. 全作品一括プレイリスト化機能
*   **UX**: ページ上部に「全作品を連続再生」ボタンを配置。
*   **動的生成**:
  *   **アプリ内**: `videos` のID配列を `?playlist=...` として動画詳細ページへ渡し、右レールの再生リストとして扱う。
  *   **YouTube**: `youtube_video_id` を連結し `playlist?list=...` のURLを生成して外部再生も提供。

### 4-2-1. 動画詳細ページとの整合
*   イベントから動画詳細へ遷移した場合、動画詳細の関連動画には当該イベント内の前後作品を優先的に含める。
*   「全作品を連続再生」から遷移した場合は、動画詳細右レールにイベント内プレイリストを表示する。
*   振り返り上映用データはイベント詳細側に常設せず、各動画詳細ページのポップアップで表示する。

### 4-3. スタッフクレジットのプレミアム演出
*   **視覚効果**: 単なるリストではなく、スタッフ名をクリックするとその人が制作に関わった作品がその場で強調表示（ハイライト）されるなどのインタラクティブな連携を実装します。

### 4-4. セクション別の抽出表示

- **フィルタ**: 「公式上映作品」「有志作品」「特別枠」などの `scheduling_type`、上映順、公開状態に基づいて、タブまたはアコーディオン形式で分割表示を行い、情報の多層化を解消します。

### 4-6. アーカイブ表示

- 終了イベントは削除せず、アーカイブ状態として公開ページに残す。
- アーカイブ状態でも、イベント説明、公開対象の代表者/運営メンバー、所属作品、公開可能な枠一覧を確認できる。
- 受付終了後は参加 CTA を出さず、「アーカイブ」「全作品を連続再生」「作品一覧」導線を優先する。

### 4-5. スロット確保時の必須バリデーション (display_name)

- **ルール**: 枠確保フォームでは `display_name` を**必須項目**とし、空欄での確保を禁止します。
- **UX**: 入力された名前は即座に「お祭り参加者リスト（スロット公開ページ）」に反映される旨を明記し、参加への意欲を高めます。
