### Known differences (RH-014; S2-forced or recorded CURRENT quirks, not behaviour improvements)
- Own slots are read with a named LIMIT (`MAX_VIEWER_SLOTS = 100`) and the JSON column is bounded to 64 KiB (UTF-8). More rows or bytes fail closed with CURRENT's `authUnavailable` shape (`loggedIn: true`). CURRENT is unbounded. Accepted by D-12 (fail-closed, no paging).
- A failed own-slots read is a 200 `authUnavailable` shape in CURRENT (separate `withDatabase` call after the viewer is known); here it shares the event statement, so it is a 503 `viewer_overlay_unavailable` (Retry-After 3). The viewer-statement failure maps to CURRENT's `getCurrentUser` failure (200, `authUnavailable: true`, `loggedIn: false`).
- If the viewer statement (statement 2) fails, the route always returns the loggedIn:false authUnavailable shape; CURRENT returns loggedIn:true when only the onboarding read fails (the two CURRENT reads share one statement here).
- Row order: CURRENT has no ORDER BY and scans `slots_event_idx (event_id, start_time)`; the route states `ORDER BY start_time, rowid` so `viewer-group-N` numbering matches (verified by the parity test).
- Pending reservation X requests are read as a newest-first list capped at 100 (CURRENT: unbounded list; the latest-1 status read is the head of the same list).
- CURRENT quirk reproduced: `slotViewerOverlay.ts` selects the event row without `visibility_status`, so `canUseSlotOperatorOverride` (needs a public event) is always false. `operatorOverrideAllowed` is false for every viewer including admins, and the staff authorization snapshot is therefore never needed. Pinned by the parity test (admin in the pre-entry window). Fixing it is a behaviour change, listed as a brush-up proposal in PR #391. Follow-up registered: FIX-0604-1 (Next fix + Hono staff snapshot in one PR, after MIG-0633).
